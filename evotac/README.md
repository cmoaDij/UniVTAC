Importing `evotac`, configuration, contracts, or legacy readers does not start Isaac. Create the task only after `AppLauncher`, using `evotac.envs.factory.create_task`; `UniVTACRLWrapper` then owns `reset`, `step`, `replay_start`, and `close`. `Action` distinguishes eight-dimensional joint targets from seven-dimensional normalized recovery increments. One accepted control holds a physical target for six 120 Hz steps. Recovery uses local world-frame rotation-vector IK at `panda_hand`, never a planned motion trajectory.

The default executable startup is livestream (`--livestream 2`, cameras enabled). Rendering validation keeps this mode so replay and policy results remain comparable. For a separate speed measurement, pass `--performance-profile`; EvoTac then uses headless/livestream=0 while retaining camera and tactile sensors, and records GPU snapshots and wall-clock rates. It must not be mixed with the validation cohort. A bare `--headless` remains rejected to avoid silently changing the experiment contract.

The detailed P0–P6 status and the proposed speed decomposition are in [the implementation status](docs/EvoTac_Implementation_Status.md), [the phase plan](docs/EvoTac_Phase_Implementation_Plan.md), and [the performance analysis](docs/Performance_Analysis_and_Optimization.md). When Isaac GPUs are occupied, run the lightweight control-contract sweep with `python -m evotac.scripts.run_fast_simulation --seeds 0 1 2 --conditions nominal C1 C2 C3`. Its result is a surrogate smoke report and must not be used as TacEx physical evidence.

Dev/test evaluation refuses an uncalibrated trigger and records the train-split calibration hash in `checks.json`. It writes the recovery trainer checkpoint and episode audit under the run directory. A train-split warm-start checkpoint is written by `train_recovery_warmstart.py`; `--allow-uninitialized-history` is only for plumbing smoke.

Outputs resolve relative to the package directory, regardless of working directory. Each run creates a manifest, all-attempt scene index, HDF5 episodes, optional scene-reference HDF5 files, and checks/error reports under `datasets/` and `runs/`. HDF5 `complete` means the recorder finalized the file; inspect `outcome.valid_trial`, `outcome.incomplete`, terminal reason and transition execution status separately. A completed file can represent a reset exception, rejected action or interruption. A zero-step rejection is an event, not a fabricated executed transition. Infrastructure errors truncate the API episode with `valid_trial=false` and `bootstrap_allowed=false`.

Legacy conversion is read-only and labels `q[i+3]` as `future_measured_qpos`. Historical rate/joint-order provenance remains unconfirmed; generated candidates are not formal training data and never recovery replay-buffer transitions.
