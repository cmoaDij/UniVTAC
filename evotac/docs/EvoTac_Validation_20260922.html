一致性问题分析与修复

已定位三类来源：快照源分支在相机同步前导出，RTX 相机缓冲可落后一帧；TacEx 的 marker simulator 每次生成 marker flow 都推进私有 NumPy RNG，而快照没有保存它；机器人关节/物体状态恢复存在小于 1e-6 的浮点误差。代码已统一源/恢复渲染路径、保存和恢复每个触觉传感器的 marker RNG，并把物理状态比较设为 1e-6 诊断界限。

修复后 dev23 的 完整审计：两个分支都完整结束（均为 object_lost、valid_trial=true），actor pose 精确相同，state_match=true；但原始图像仍非逐像素一致（wrist 最大差 81，触觉最大差约 18），因此 observations_match=false。代码曾把候选落在四次控制渲染范围内误判为 paired_valid=true，现已改为 fail-closed：经验渲染范围永远不能替代严格观测或隐藏状态证据。

快照审计失败证据

原始 dev seed 23 的 head RGB 最大绝对差 16、wrist RGB 最大绝对差 143，right tactile RGB/rgb_marker 最大绝对差 17；修复后仍存在 RTX 相机和触觉光学输出差异。test_status=not_started_pending_causal_gate，因此共享状态不能作为因果反事实依据，恢复分支结果不能归因于 EvoTac。
