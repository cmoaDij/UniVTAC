## 2. insert_hole 中实际有什么

以 `data/isaac51/insert_hole/hdf5/0.hdf5` 为例，包含 189 帧：

| 字段 | 实际格式 | 可用范围 |
|---|---|---|
| `observation/head/rgb`、`observation/wrist/rgb` | JPEG 字节串；抽检解码为 270×480×3 | 视觉 ACT、图像预处理与场景观察 |
| `tactile/{left,right}_tactile/{rgb,rgb_marker}` | JPEG 字节串；抽检解码为 240×320×3 | 原始触觉输入与正常接触统计 |
| `tactile/…/depth`、`press_depth` | float32，逐帧 240×320 | 仿真诊断；部署权限需单独确认 |
| `tactile/…/marker` | float32，逐帧 2×63×2 | 触觉标记点分析，先明确两个平面的含义 |
| `tactile/…/pose` | float32，逐帧 7 维 | 安装/位姿诊断，不能无审查送入 actor |
| `embodiment/joint` | float32，逐帧 9 维 | 关节状态，需明确 7 臂关节与双指映射 |
| `embodiment/ee` | float32，逐帧 7 维 | 末端状态，坐标定义按采集实现核对 |
| `actor/prism`、`prism_base`、`slot` | float32，逐帧 7 维 | 训练/离线评价真值，不能混入部署输入 |
| `step`、`atom/id`、`atom/tag` | 步号、脚本动作标记 | 时间轴辅助和离线分段；不是策略输入 |

100 条 `insert_hole` 轨迹的 metadata 中，`rotate=π` 有 62 条，`rotate=0` 有 38 条。可以据此做父场景级分层划分，但这是隐藏场景标签，不输入策略。

两指关节的最大差约 `1.08e-6 m`，说明本批数据中两指状态很接近。仍应核对关节名称/顺序，再用显式映射形成 8 维 `[7 个臂关节, 夹爪标量]`；不能依靠 9→8 随意切片。

## 3. 与 EvoTac 需求的关键差距

### 3.1 时间轴很可能是 60 Hz，但不是已证实的 20 Hz 数据

全部保存帧 `Δstep=2`，metadata 的 `cost_step=cost_physics_step`；当前 `task_config/clean51.yml` 设定物理/采集 120 Hz、保存 60 Hz。这些证据与 60 Hz 保存一致。

**保留不确定性：** 原文件未保存频率配置。目录名 `isaac51` 和当前 YAML 不能单独证明每条轨迹的历史采集参数。需补充原采集日志/配置，或通过受控重放进一步核验。

若确认原始保存为 60 Hz，20 Hz 候选示范可以每三个原始采样点形成一个时间间隔：

```text
输入：o[i], q[i]       i = 0, 3, 6, …
候选目标：q[i + 3]   要求 i + 3 < N
持续时间：0.05 s
```

这里的目标是“未来测得状态构成的模仿代理目标”，不是恢复出的原始执行命令。按固定相位 0 计算，100 条轨迹可形成 6,315 个这样的 20 Hz 候选样本。其他采样相位不能被当成新的独立父场景。

**不能直接使用现有 `downsample_factor=3` 完成这种转换。** `envs/utils/data.py::batch_gather_hdf5` 当前将 `state=q[:-1][::3]` 与 `action=q[1:][::3]` 配对，目标仍只领先一个原始帧，输入间隔却变成三个帧；这不等于 50 ms 目标。应在 `evotac/` 内实现明确的时间配对转换，保持原预处理器不变。

ACT 动作块长度也需按实际时间重新配置：50 个动作在 60 Hz 下约 0.83 s，在 20 Hz 下为 2.5 s，不能只修改采样频率而不检查动作块时间跨度。

### 3.2 文件存的是测得关节状态，缺少独立执行命令

HDF5 没有 `proposed_action`、`commanded_action`、`applied_action` 或对应接受/失败标志。当前采集代码保存的是 `_get_observations()`；ACT 预处理器将下一帧 `embodiment/joint` 用作动作标签。

该约定可用于模仿学习尝试，但不足以验证控制命令与物理执行响应的差别，也不能直接写入 EvoTac SAC replay buffer 充当真实动作。更无法从这些 9 维状态直接得到已执行的 7 维归一化恢复动作。

当前原任务 `move` 默认可使用 `force=True` 直接写关节位置，而 EvoTac 计划采用 `force=False`。本批文件未记录 force/PD 参数，不能断言数据必然来自哪一种控制方式；必须检查新物理驱动下的轨迹跟踪和闭环结果。

### 3.3 没有完整抓取前缀，也没有两类参考图

`insert_hole` 的首帧 step 范围为 442–546；样例 0 从 step 478 才开始。结合当前 `in_pre_move` 阶段不保存示范的逻辑，这些记录与“已经抓好并接近孔口，再保存插入动作”一致。

因此它们适合训练当前任务初始化之后的插入策略，不能据此声称已有完整的抓取—接近示范。若按 60 Hz 解释，各轨迹已保存部分仅约 2.60–4.07 s，中位约 3.03 s。

缺少显式空载参考、稳定持握但未接触外部目标的参考及其有效性。首帧可能已接近或接触孔壁，不应将其伪装为 `T_empty` 或 `T_grasp`。可先使用原触觉图像；正式 EvoTac 参考应在新运行中正确采集。

这些数据不能直接提供阶段 1 要求的完整 `scene_ref`：没有完整前缀命令、控制器状态、参考事件和策略缓存。可用原种子重建场景再生成新的前缀，但必须记录重建误差。

### 3.4 文件编号不是可靠的重放种子

`insert_hole` 的文件编号为 0–99，但 `source_seed` 范围为 0–761，其中 60 条已经重编号。例如：

| 文件 | metadata 中 `seed` | `source_seed` |
|---|---:|---:|
| `40.hdf5` | 40 | 41 |
| `97.hdf5` | 97 | 759 |
| `98.hdf5` | 98 | 760 |
| `99.hdf5` | 99 | 761 |

重新生成环境优先使用 `source_seed`，同时保留原文件 ID 和环境版本。直接 `reset(seed=int(filename))` 会使这些回合与来源不符。每个任务内部未发现重复 `source_seed`，不同任务的同号种子不能当成同一父场景。

种子范围包含间隔，不代表所有缺失种子均失败；不能用 `100/762` 估计成功率。当前目录只保存筛选后的成功记录。

### 3.5 缺少失败分布、效果标签和逐模态采样时间

全部已保存回合均标为成功，没有对应技能版本、恢复开始/交还、后续 ACT 成功、恢复预算或不同技能在同一起点上的结果矩阵。

此外，共享 step 索引并不能证明相机/触觉完全同时采样。没有逐模态时间戳、帧龄及有效性，因而无法用旧文件完成“无未来帧、低延迟同步”的完整验收。

图像采用 JPEG，适合常规训练尝试；微小触觉差分和重建误差的统计需要考虑压缩影响，不能用旧 JPEG 与新无损数据混合校准容差。颜色通道也应复用并核验原编码/解码约定，避免额外 RGB/BGR 交换。

## 4. 哪些可以复用，哪些必须补充

| 用途 | 判断 | 处理方式 |
|---|---|---|
| 阶段 1 HDF5 读取、图像解码和字段映射 | **可以现在使用** | 优先使用 insert_hole，白名单隔离 actor/atom/metadata |
| 阶段 1 真实步进、时间同步、中断和异常落盘验收 | **不能替代新运行** | 需要固定控制入口的短 GPU 集成 |
| 阶段 2 视觉 ACT | **可作为候选训练/暖启动数据** | 确认版本、60→20 Hz 配对、9→8 维映射，随后仿真验证 |
| 正常接触统计、触觉编码器初始化 | **有条件可用** | 先做图像质量/时序检查；无参考量保持无效，不伪造 |
| 异常监测器阈值 | **只能提供正常分布** | 必须补采真实卡住、滑落、控制失败等异常分布 |
| 阶段 3 恢复技能 SAC | **不能直接作为恢复 transition** | 补采带实际动作契约、预算及终止语义的恢复交互 |
| 阶段 4 效果表征、技能选择标签 | **不能直接使用为效果监督** | 对匹配起点执行冻结技能及固定后续策略，记录真实结果 |
| 阶段 5 新条件适应与接纳 | **不能替代** | 需要新条件、独立接纳场景和完整成本记录 |
| 正式总体成功率评估 | **不能用成功筛选集估计** | 使用独立、未按专家成功筛选的场景清单 |

其他七个任务先保留作为后续可选表征数据；当前计划是单任务，不将其动作和成功标签混入 `insert_hole` 策略或恢复学习。多任务初始化不是阶段 1 的必要工作。

## 5. 建议的复用流程与路径

保持 `data/isaac51/` 为只读旧数据源，不移动、不重命名、不覆盖，也不立即复制 242 GiB 数据。用户“新增代码和数据都放 `evotac/`”的要求适用于新增产物；引用已有源文件即可满足，不需要搬迁原数据。

```text
evotac/
    scripts/audit_legacy_data.py              # 本次已新增并运行
    docs/Isaac51_Existing_Data_Assessment.md  # 本文
    runs/legacy_audit/isaac51_audit.json      # 本次实际检查记录，Git 忽略
    configs/legacy_insert_hole.yaml          # 后续：原始数据路径、配对和映射配置
    datasets/legacy_insert_hole/             # 后续：转换后的 ACT 候选数据与来源清单
    datasets/phase1/                         # 后续：新控制接口生成的严格契约数据
```

推荐顺序：

1. 以这 100 条 insert_hole 为候选成功示范池，保存源文件路径、source_seed、文件大小和转换版本；正式训练前增加内容校验标识。
2. 先按父场景划分训练/开发/留出集，例如 80/10/10，并尽量保留 62:38 场景类型比例。归一化统计仅从训练集计算；分帧、裁剪和不同抽样相位均继承父场景划分。这个成功示范留出集不等于正式评估场景集。
3. 在独立转换器中实现时间配对、关节映射和相机命名。原预处理器默认找 `data/<task>/<config>/`，与当前 `data/isaac51/<task>/` 不匹配；其 `cam_head` 与视觉 ACT 的 `cam_high` 命名也需适配，不直接运行旧脚本覆盖全局 `SIM_TASK_CONFIGS.json`。
4. 先选少量训练/开发轨迹，验证新控制器在同一 source_seed 下的初始观测、20 Hz 目标跟踪、最终成功判定及触觉行为。回放参考轨迹只检验执行兼容性；还需 ACT 闭环运行才能判断策略是否可用。
5. 若兼容，则继续复用这批成功示范，减少重采；若存在明显控制/时序差异，可保留它们用于暖启动，再补采匹配新控制器的数据。是否全部重采由结果决定。
6. 无论成功示范是否可复用，都要补采：空载/稳定抓取参考、完整物理前缀、失败和执行异常、真实恢复 transition，以及后续技能效果分支。

