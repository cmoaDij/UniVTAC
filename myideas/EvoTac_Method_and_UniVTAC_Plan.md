# 第一部分：研究定义

<a id="section-1"></a>

## 1. 方法概述

### 1.1 一句话定义

**EvoTac 利用触觉与动作历史判断“当前接触状态适合哪一种恢复”，通过强化学习获得连续接触技能，并以恢复后的真实任务结果组织经验、复用技能和验证更新，从而在接触条件变化时持续适应。**

这里的重点不是“给策略多加一种传感器”，而是改变经验的组织依据：

$$
\text{按触觉外观相似性组织经验}
\quad\longrightarrow\quad
\text{按恢复行为的下游效果组织经验}
$$

例如，不同物体的触觉图像可能差别很大，但都适合“回撤后重新对齐”；相反，两段外观近似的触觉历史，可能分别需要向左和向右纠正。我们希望学习到的表示能够区分后一种情况，同时支持前一种情况下的经验复用。

这是**待实验检验的研究假设**，不是现有结果。

### 1.2 三个核心组成

| 组成 | 具体职责 | 不应混淆成什么 |
|---|---|---|
| 触觉—动作历史表征 | 提取当前接触过程对恢复决策有用的信息 | 不等于物体类别识别，也不等于恢复完整物理状态 |
| 强化学习接触技能 | 学习微调、回撤、重新对齐等连续动作及其时序 | 不只是手写动作模板，也不只是调整触发阈值 |
| 结果驱动的持续适应 | 根据真实恢复结果改进选择、更新技能，必要时扩展技能库 | 不等于自动保存轨迹，也不等于无条件持续训练 |

第一版冻结视觉基础策略，重点学习触觉接触控制与恢复。基础策略可选 ACT，不要求使用语言模型。ACT 是已有动作分块模仿学习方法，使用它是实现选择，不构成本方法的创新。[R16](#ref-r16)

### 1.3 总体闭环

```text
任务目标 + 视觉 + 本体状态
              |
              v
       冻结的基础策略
              |
              v
      正常执行 / 接触微调 <-----------------------------+
              |                                       |
              v                                       |
     触觉—动作历史与运行时监测                           |
              |                                       |
       正常 --+--> 继续执行                             |
              |                                       |
            异常                                      |
              v                                       |
       暂停基础动作块                                  |
              |                                       |
              v                                       |
    预测已有技能的恢复效果                               |
              |                                       |
      有可靠技能 ----> 选择并闭环执行恢复                  |
              |                    |                  |
      无可靠技能                   v                  |
              |           达到交还条件 / 超时            |
              v                    |                  |
    停止本次尝试并记录               v                  |
    进入后续仿真训练队列      清空旧动作块，重新观察 --------+
              |
              v
   保存成功、失败、中断、成本与策略版本
              |
              v
   更新结果表征 / 微调旧技能 / 训练新候选
              |
              v
      新条件验证 + 旧条件回归测试
              |
       通过：替换或加入技能库
       未通过：保留旧系统
```

闭环必须同时包含两个层次：**单次执行内的感知—动作闭环**，以及**跨回合的交互—学习—验证闭环**。仅有失败后的日志整理，不构成这里所说的持续适应。

### 1.4 当前明确不做的事情

不训练未来视觉或触觉生成模型；不学习完整动力学模型进行想象规划；不从零预训练通用触觉基础模型；不要求大语言模型生成恢复代码；不把自动发现无限种技能作为第一版目标。

本方法允许使用已有物理仿真器执行分支试验。**使用物理仿真器获取真实仿真交互结果，不等于训练学习型世界模型。**

## 2. 科学问题与创新边界

### 2.1 为什么“触觉 + RL + 恢复”还不够？

已有工作已经覆盖多个基础部件：

| 已有方向 | 代表研究与已涉及内容 | 对 EvoTac 的约束 |
|---|---|---|
| 触觉残差强化学习 | OmniTacTune：冻结视觉策略，以触觉残差进行在线 RL 适配。[R05](#ref-r05) | 不能把“冻结视觉策略 + 触觉残差 RL”单独声称为创新 |
| 快慢视觉—触觉策略 | RDP：慢速动作结构与快速触觉闭环控制。[R06](#ref-r06) | 双速率控制应作为架构依据 |
| 接触门控融合 | TacVLA：接触感知门控与触觉 token 融合。[R07](#ref-r07) | 接触门控本身不是空白方向 |
| 接触相关恢复 | CADRE：利用接触描述学习动态接取，并恢复到适合继续任务的状态。[R08](#ref-r08) | 必须区分其灵巧手动态接取设置与本方案的触觉插入恢复 |
| 验证门控自进化 | Zetta：冻结基础策略，演化代码形式的运行时 critic 与恢复技能。[R09](#ref-r09) | “监测—恢复—验证—积累”不是独立的新贡献 |
| 失败驱动技能与概念学习 | ReSYNC：从恢复经验中学习技能与关系概念，用于抽象规划。[R10](#ref-r10) | “从失败中增长技能库”不是充分的新意 |
| 技能成功率用于选择 | SayCan：以技能可供性/价值评估技能的执行可行性。[R13](#ref-r13) | 成功概率预测和技能选择本身已有基础 |
| 仿真触觉 RL | TacCoRL：利用模拟接触交互与任务奖励优化触觉增强策略。[R15](#ref-r15) | “在仿真里用触觉做 RL”不是充分的新意 |

因此，本方法应把研究问题收敛到：**触觉恢复经验应按什么方式组织，才能在接触条件变化时高效复用，并驱动必要而非盲目的能力扩展？**

### 2.2 三个可检验的研究问题

**RQ1：控制相关表示。** 与通用触觉表示、简单多模态融合以及单独的技能成功率预测相比，加入“恢复效果一致性”约束的表示，能否更好地区分需要不同纠正的接触状态？

**RQ2：经验与技能迁移。** 在物体几何、抓取偏差或初始接触条件改变时，按照恢复效果组织的记忆，能否减少技能重新学习所需的交互？

**RQ3：持续适应。** 当新条件按阶段到来时，系统能否通过“先复用、再更新、必要时扩展、验证后接纳”获得收益，同时控制旧能力退化与技能库规模？

三个问题分别对应表示、迁移和持续学习，不能用一张总体成功率表同时替代。

### 2.3 推荐的贡献层级

**主贡献候选：恢复效果驱动的触觉经验组织。** 在固定恢复技能与固定后续策略的条件下，用实际恢复结果监督触觉—动作历史表示，并将表示用于技能选择和跨条件经验检索。

**第二贡献候选：能力不足驱动的适应机制。** 区分“选择错误”“既有技能能力不足”和“观测不足”，按原因更新，而不是把每次失败都变成一个新技能。

**系统与实验贡献：可审计的触觉恢复闭环。** 明确交还条件、最终恢复标签、版本一致性、交互预算及持续学习协议，使结论可以复现。

上述贡献是否成立，需要与强基线比较。**如果只实现一个多头成功率分类器加技能选择器，没有展示表示结构、经验迁移或持续适应的额外价值，论文创新仍然偏弱。**

### 2.4 “自进化”的操作性定义

本文把自进化限定为：系统利用自身交互产生的数据，在预先设计的更新机制下，改变经验表示、技能选择能力或技能参数，并通过独立验证决定是否保留变化。

这不是无条件的自主发现，也不是性能单调提升的理论保证。若只完成固定技能库中的策略微调，应称为“持续适应”；只有实现并验证能力驱动的结构扩展后，才能进一步强调“技能库自扩展”。

## 3. 问题建模

### 3.1 部分可观测接触操作

将任务视为部分可观测决策过程。环境真实状态为 $s_t$，部署可见观测为：

$$
o_t=(V_t,T_t,P_t,g,\nu_t)
$$

其中 $V_t$ 是视觉，$T_t$ 是双指触觉，$P_t$ 是本体状态，$g$ 是任务目标，$\nu_t$ 包含传感器有效性、时间戳，以及机器人已知的控制模式和剩余预算。

隐藏状态可能包括接触位置、摩擦、微小姿态偏差和局部形变。策略不直接读取这些真值，而使用历史：

$$
H_t=\{o_{t-K+1:t},a^{\mathrm{exec}}_{t-K:t-1}\}
$$

$$
h_t=F_\phi(H_t),\qquad z_t=G_\phi(h_t)
$$

$h_t$ 是结果学习分支的历史特征，$z_t$ 用于恢复效果预测与经验组织。控制分支另外计算：

$$
h_t^\pi=F_{\phi_\pi}(H_t)
$$

两个分支可以共享**冻结的图像前端**，但第一版不共享随效果监督更新的时序编码器参数。评估技能时冻结 $\phi_\pi$、actor、终止机制及全部预处理；效果学习只更新 $\phi,\psi$。

这一分离避免“训练表示时改变被评估技能，导致效果标签随之失效”。控制表示保留动作所需的局部细节，不强制所有动作信息都经过效果表示 $z_t$。

记录的是实际执行动作，而非仅记录策略原始输出。动作裁剪、暂停、低层控制器和执行失败都会使两者不同。

### 3.2 基础策略与恢复技能

基础策略：

$$
a_t^0=\pi_0(V_t,P_t,g)
$$

恢复技能集合：

$$
\Omega=\{\omega_k\}_{k=1}^{M},
\qquad
\omega_k=(\mathcal I_k,\pi_{\theta_k},\beta_k,B_k)
$$

$\mathcal I_k$ 是技能适用范围，$\pi_{\theta_k}$ 是连续控制策略，$\beta_k$ 是终止/交还机制，$B_k$ 是最大恢复预算。适用范围不能只由未经校准的高分决定，还应考虑训练数据覆盖和安全限制。

为避免符号混淆，本文区分：

| 名称 | 符号 | 回答的问题 |
|---|---|---|
| 运行时监测器 | $D_\xi$ | 是否出现异常，需要暂停或恢复？ |
| 连续动作 RL critic | $Q_{\eta,k}$ | 某个连续动作在当前恢复策略下价值多大？ |
| 恢复效果预测器 | $U_\psi$ | 某个完整恢复技能执行后，后续任务能否完成？ |

Zetta 中的运行时 critic 与 SAC 中的 $Q$ 网络不是同一个概念。[R09](#ref-r09)[R12](#ref-r12)

### 3.3 恢复效果必须带有“后续策略”和“预算”

固定一个技能版本 $v_k$、后续执行策略 $\pi_{\mathrm{cont}}$、任务目标 $g$ 与剩余预算 $B_{\mathrm{rem}}$，定义：

$$
p_k(H_t,g,B_{\mathrm{rem}})
=
\Pr\!\left(
Y_{\mathrm{task}}=1
\mid H_t,\omega_k^{v_k},\pi_{\mathrm{cont}},g,B_{\mathrm{rem}}
\right)
$$

第一版令 $\pi_{\mathrm{cont}}$ 为冻结基础策略及固定的正常接触控制模块，并在一次标签试验中**禁止再次调用其他恢复技能**。

这样，标签回答的是“这一次恢复是否让固定后续策略重新具备完成任务的能力”，而不是“系统经过无限次重试后最终是否成功”。

多次恢复链可以在后续完整系统中启用，但必须另外记录链级效果，并固定调度规则。不得把一次恢复效果和多次恢复链的成功概率混合训练。

# 第二部分：方法设计

<a id="section-4"></a>

## 4. 触觉信息处理：测到了什么，保留什么？

### 4.1 传感器语义

第一版面向双指光学触觉。GelSight 类传感器通过弹性表面形变提供局部几何与运动线索；力和滑移通常需要标定、几何重建、标记点分析或学习推断，不能直接把 RGB 触觉图像称作已测得的三维力。[R14](#ref-r14)

本方案使用三类输入：

| 输入 | 建议内容 | 使用原则 |
|---|---|---|
| 低维接触线索 | 接触标志、面积、中心、左右差异、形变变化 | 可解释、低成本；不可获得的量不强行填入 |
| 学习型触觉特征 | 当前原图、参考差分的编码结果 | 保留手工特征遗漏的接触模式 |
| 时间与动作上下文 | 本体状态、实际动作、接触建立/丢失、采样间隔 | 区分被动滑移与主动调整等历史依赖过程 |

指尖传感器直接观测的是“手指—物体”界面。物体与孔壁的接触可能通过受力传递影响指尖，但不能据此假定能唯一恢复孔壁的完整接触状态。该可辨识性必须通过数据验证。

### 4.2 空载参考与稳定抓取参考

对每个传感器保留空载图像 $T^{\mathrm{empty}}$，以及在稳定抓取、尚未接触外部目标时获得的参考 $T^{\mathrm{grasp}}$：

$$
\Delta T_t^{\mathrm{empty}}=T_t-T^{\mathrm{empty}}
$$

$$
\Delta T_t^{\mathrm{grasp}}=T_t-T^{\mathrm{grasp}}
$$

原图与两类差分有不同作用：空载差分提供接触形变线索；抓取差分帮助分析操作过程相对初始持握的变化。不能仅用差分而完全丢弃原始状态。

这是预处理设计，不作为独立创新。参考只在明确稳定且无异常的阶段建立或更新，不能在卡住时自适应更新，把异常“吸收”进背景。无可用抓取参考时提供有效性掩码，不能伪造为可靠零差分。

### 4.3 编码方式

建议双指共享图像编码器，但加入传感器身份与坐标信息：

$$
e_t^L=E_T(T_t^L,\Delta T_t^L,\mathrm{id}_L),\quad
e_t^R=E_T(T_t^R,\Delta T_t^R,\mathrm{id}_R)
$$

$$
x_t=
[e_t^L,e_t^R,f_t^{\mathrm{contact}},E_V(V_t),P_t,
a^{\mathrm{exec}}_{t-1},\nu_t]
$$

$$
h_t=\operatorname{GRU}_\phi(x_{t-K+1:t}),\qquad
z_t=\operatorname{MLP}_\phi(h_t)
$$

共享权重不意味着可以随意交换左右指。接触中心方向、安装旋转和机器人坐标系必须一致解释。

Sparsh 或 UniVTAC Encoder 可作为初始化与基线；它们已有触觉表示学习基础，但在当前任务上的最优选择需要验证，不能默认预训练模型必定优于小型编码器。[R11](#ref-r11)[R01](#ref-r01)

### 4.4 不把“无接触”和“传感器失效”混为一谈

详细触觉特征可以门控，但接触标志、接触丢失事件、采样有效性和近期历史应始终进入系统。

稳定抓握时指尖可能一直处于接触，因此二值“接触为真”不能直接判定外部插入是否受阻。运行时判断需要结合相对变化与动作进展。

数据缺失时用有效性掩码与上一帧时间戳表示。不能用全零触觉图像同时代表“无接触”“掉帧”“相机异常”和“归一化后的正常帧”。

### 4.5 时间对齐与触觉利用审计

按控制时刻采样历史，只使用该时刻及以前的观测。视觉可以较慢更新，但应传入观测年龄；触觉帧晚到时，不能在训练中把未来帧对齐到过去动作。

为检验策略是否真正利用触觉，后续实验应包含合理的传感器噪声、延迟、短时缺失，以及同任务、近似视觉条件下的触觉历史替换测试。替换属于诊断干预，不能单凭随机打乱造成性能下降就声称获得了因果理解。

## 5. 策略融合与执行机制

### 5.1 两条控制路径

正常路径保留基础策略，必要时叠加有界触觉微调：

$$
a_t^{\mathrm{nom}}
=
\operatorname{Limit}
\left(a_t^0+\lambda_t\delta a_t\right),
\quad
\delta a_t=\pi_{\mathrm{micro}}(h_t^\pi,a_t^0,g)
$$

恢复路径暂停基础策略，由选定恢复技能独立控制：

$$
a_t^{\mathrm{rec}}
=
\operatorname{Limit}\left(\pi_{\theta_k}(h_t^\pi,g)\right)
$$

$$
a_t^{\mathrm{cmd}}
=
\begin{cases}
a_t^{\mathrm{nom}}, & m_t=\mathrm{NORMAL}\\
a_t^{\mathrm{rec}}, & m_t=\mathrm{RECOVERY}\\
a_t^{\mathrm{stop}}, & m_t=\mathrm{STOP}
\end{cases}
$$

这里的微调模块可以在完成触觉残差基线后冻结，并被所有恢复方法共享。**最小版本允许令 $\lambda_t=0$**，先只研究事件触发的恢复，避免同时学习多个模块导致归因不清。

“有界残差 + 独立恢复”解决的是控制职责问题：需要回撤时，不能让持续前推的基础策略抵消恢复动作。该架构是本研究的基础，不单独作为新贡献；相关触觉残差与快慢控制已有先例。[R05](#ref-r05)[R06](#ref-r06)

### 5.2 动作空间统一

采用末端位姿增量加夹爪增量时：

$$
a_t=[\Delta x,\Delta y,\Delta z,\Delta r_x,\Delta r_y,\Delta r_z,\Delta w]
$$

平移用米，旋转采用明确约定的轴角增量或接口所需表示，夹爪增量单位由控制接口确定。不得将欧拉角差、轴角向量和四元数分量混用。

若基础策略输出关节位置目标，应选择以下一种一致路径：所有微调也在关节空间进行；或把关节目标经运动学转换为末端目标，再形成相同坐标系下的末端增量。独立恢复可以通过明确切换控制模式使用末端动作，但切换时必须重置目标缓存，避免位置命令跳变。

$\operatorname{Limit}$ 表示幅度、速度、工作空间及关节限制，**不是严格接触安全保证**。正常路径与恢复路径都要通过同一个执行与保护接口。

### 5.3 有限状态机

| 状态 | 进入条件 | 行为 | 退出条件 |
|---|---|---|---|
| NORMAL | 回合开始或交还完成 | 执行基础策略/微调 | 任务成功、异常、硬停止 |
| SELECT | 异常达到触发条件 | 暂停基础动作，选择技能 | 获得可靠技能或进入停止 |
| RECOVERY | 技能通过适用性检查 | 闭环执行一个恢复技能 | 交还条件、恢复预算耗尽、硬停止 |
| RESUME | 恢复允许交还 | 清空旧动作块，重新观察并查询基础策略 | 回到 NORMAL |
| STOP | 过载、控制失效、无可靠技能或预算耗尽 | 停止本次尝试并记录原因 | 环境重置 |

第一版用明确的状态机，不额外训练高层 RL 调度器。学习重点放在恢复表征、技能效果和低层连续控制。

### 5.4 交还不等于成功

交还条件可包括：负载回到允许范围、握持未明显失稳、机器人重新获得可控运动、局部观察满足预定条件，并持续若干有效观测周期。

这些条件只说明“可以尝试重新交给基础策略”，不说明任务已经恢复成功。最终标签要通过后续完整执行获得。

交还时必须丢弃暂停前尚未执行的动作块，重新获取观测。否则即使恢复动作有效，旧动作块仍可能把机器人带回相同失败状态。

## 6. 核心方法：恢复效果驱动的触觉表征

### 6.1 恢复效果向量

对一个可重复生成的失败前历史 $H_i$，在冻结技能集合与固定后续策略下，定义：

$$
\mathbf r(H_i)
=
[p_{i1},\ldots,p_{iM},
\bar c_{i1},\ldots,\bar c_{iM},
u_{i1},\ldots,u_{iM}]
$$

其中 $p_{ik}$ 是技能 $k$ 执行后任务完成的概率，$\bar c_{ik}$ 是归一化恢复代价，$u_{ik}$ 是规定评估范围内发生约束违规的概率。时间、负载与动作代价可以分别存储，再在选择时组合。

该向量必须关联技能版本、后续策略版本、目标与预算。两个状态的向量相似，表示它们在**当前技能集合与评估协议下具有近似恢复效果**；不意味着动力学完全相同，也不是严格双模拟等价。

### 6.2 标签如何获得？

在仿真中对失败状态进行有限分支试验：

```text
恢复/重放失败前的完整起点
    -> 固定技能 k
    -> 执行到交还、恢复超时或硬停止
    -> 若可交还，运行冻结的后续策略
    -> 不允许第二次恢复
    -> 记录最终任务完成、恢复代价、违规与终止原因
```

对同一状态—技能组合进行重复试验时，应明确随机性来自哪里：环境扰动、传感噪声或策略采样。若采用确定性策略和完全相同状态，反复重复同一轨迹不能提供丰富的接触泛化证据。

假设某组合获得 $n_{ik}$ 次有效试验、其中 $s_{ik}$ 次任务完成，可用带平滑的估计：

$$
\tilde p_{ik}
=
\frac{s_{ik}+1}{n_{ik}+2}
$$

它是用于小样本稳定化的 Beta-Bernoulli 估计示例，不是已校准的真实成功概率。未执行的组合保持 `observed = false`；即使先验均值为 0.5，也不能据此生成可靠监督或断言有一半成功机会。

对训练失败、数值异常和记录不完整的试验单独标记。真正因机器人动作导致的任务失败应保留为负样本；仿真器崩溃导致结果未知的样本不能自动标为技能失败。

### 6.3 多头效果预测

通过部署可获得的历史预测技能效果：

$$
(\hat p_{ik},\hat c_{ik},\hat u_{ik})
=
U_\psi(z_i,g_i,B_i,k)
$$

第一版效果预测器和经验检索依赖 $z_i$，底层 actor 则使用独立的 $h_i^\pi$。效果预测器不绕过 $z_i$ 直接读取完整历史；带绕过连接的模型可作为额外消融，但不与当前主实现混用。

最直接的监督为：

$$
\mathcal L_{\mathrm{out}}
=
\frac{1}{\sum_{i,k}m_{ik}}
\sum_{i,k}m_{ik}
\left[
\operatorname{BCE}(\hat p_{ik},y_{ik})
+
\lambda_c\operatorname{Huber}(\hat c_{ik},c_{ik})
+
\lambda_u\operatorname{BCE}(\hat u_{ik},u_{ik}^{\mathrm{obs}})
\right]
$$

$m_{ik}$ 表示有可靠标签。训练可以按单次有效试验计算二元损失；重复试验形成的经验概率主要用于效果距离与分析。样本数严重不均衡时，需报告按实际访问分布与按场景均衡两种训练/评估结果，避免热门状态压制稀有失败。

**只使用这个损失时，本质上是技能效果/可供性学习。** 它是必要对照，不足以单独支撑“新的恢复效果表征”这一较强主张。[R13](#ref-r13)

### 6.4 用实际效果监督表示的几何结构

在有重叠试验的状态对 $(i,j)$ 上，令：

$$
\mathcal K_{ij}
=
\{k:m_{ik}=1,\ m_{jk}=1,\ \text{版本与评估协议兼容}\}
$$

以实际重复试验的统计量构造目标距离：

$$
d^{\mathrm{out}}_{ij}
=
\frac{
\sum_{k\in\mathcal K_{ij}}w_{ijk}
\left[
(\tilde p_{ik}-\tilde p_{jk})^2+
\lambda_d(\tilde c_{ik}-\tilde c_{jk})^2+
\lambda_s(\tilde u_{ik}-\tilde u_{jk})^2
\right]
}{
(1+\lambda_d+\lambda_s)\sum_{k\in\mathcal K_{ij}}w_{ijk}
}
$$

所有代价先用训练集确定的尺度做有界单调变换，映射至 $[0,1]$，并在测试时固定该变换；上述分母使目标距离也位于 $[0,1]$。$w_{ijk}$ 反映有效试验数与统计可靠性，不能只由网络自身的“自信”给出。

对归一化表示 $\bar z_i=z_i/\|z_i\|$，可使用：

$$
\mathcal L_{\mathrm{metric}}
=
\mathbb E_{(i,j)}
\operatorname{Huber}
\left(
\frac{\|\bar z_i-\bar z_j\|_2^2}{4}
-
\operatorname{sg}\!\left[d^{\mathrm{out}}_{ij}\right]
\right)
$$

其中 $\operatorname{sg}$ 表示停止梯度。若目标距离不宜精确拟合，可改用有置信间隔约束的正负对或排序损失。

结果学习分支的训练目标为：

$$
\mathcal L_{\mathrm{repr}}
=
\mathcal L_{\mathrm{out}}
+
\lambda_m\mathcal L_{\mathrm{metric}}
$$

先用 $\lambda_m=0$ 建立预测基线，在具有足够可靠效果标签后再增加距离约束。该损失不反向更新冻结的控制分支。

这是当前提出的候选实现，不是已验证最优损失。实际训练只在足够覆盖的状态对上启用，避免用一次偶然成功把不同状态错误拉近。若重叠技能过少，第一版先进行效果预测，不强行启用距离监督。

最重要的监督边界是：**不要直接使用同一个网络尚未校准的预测，制造相似性标签，再用这些标签证明网络学会了恢复等价。** 目标应尽量来自独立交互统计，或来自与评估分离的冻结教师，并明确后者的局限。

### 6.5 保留“恢复方式相同，动作细节不同”的差异

例如，两个状态都适合平移纠正，但一个需要较大位移，另一个只需要微调。若把完整 actor 输入压成同一个向量，可能损害控制精度。

因此采用两层表示：

$$
z_t \longrightarrow \text{技能选择、效果预测、经验检索}
$$

$$
(h_t^\pi,k,g) \longrightarrow \text{具体连续恢复动作}
$$

$z_t$ 追求对恢复效果有意义的相似性，独立的 $h_t^\pi$ 保留实时几何与运动细节。效果表示通过技能选择、初始化和经验回放影响控制学习，第一版不把正在变化的 $z_t$ 直接作为正式 actor 的输入。跨任务比较还应共享坐标约定和技能语义；对于语义不兼容的技能集合，不强制把效果向量对齐。

### 6.6 表示怎样真正影响学习？

在新条件出现时，使用 $z_t$ 检索旧记忆，选择效果相似且版本兼容的场景，用于以下用途：

**选择初始化技能。** 优先复制或调用在相关旧场景中有效的技能，而不是随机训练。

**组织 replay。** 在当前条件数据之外，混入相似旧场景的有效恢复数据及必要的失败反例，帮助保留已有能力。

**决定需要更新哪里。** 如果旧技能在新状态中实际有效，只修正选择器；如果确实无效，才更新连续控制。

不能把某个状态上的旧动作轨迹直接原样当成新状态的正确动作。经验复用是带状态与动作信息的训练、初始化或检索，不是无坐标校正的动作复制。

### 6.7 必须进行的核心消融

完整方法至少应与“相同数据、相同网络规模、仅 $\mathcal L_{\mathrm{out}}$ 的成功率预测器”比较。还应关闭效果驱动检索，保留其他模块，验证收益是否确实来自表示与记忆组织。

若加入 $\mathcal L_{\mathrm{metric}}$ 无收益，应如实保留结果，重新判断主贡献是否应转向数据采样或持续适应，而不是仅通过命名把普通分类器包装成新机制。

## 7. 强化学习：学习连续恢复，而不是只学规则

### 7.1 技能初始化

第一版采用少量有行为偏置的技能头，例如“回撤后再接近”“横向对齐”“姿态调整”。这些名称用于初始化课程与分析，不意味着最终行为完全手写，也不意味着已经实现无监督技能发现。

可从短脚本或成功局部轨迹暖启动，然后用强化学习学习动作幅度、方向、时序和反馈响应。若全部技能被同一奖励、同一初始化和同一数据训练，可能收敛成相同策略；应检查它们的行为差异及互补成功率。

最小实现保留 2—3 个互补技能。各技能可以共享冻结图像编码器及已固定的控制历史主干，使用独立小型控制头。更新共享控制主干时，所有依赖它的技能都视为版本改变，并重评受影响标签；第一版优先只更新技能头。

### 7.2 强化学习目标

以 SAC 作为连续动作学习的默认起点。SAC 是已有的离策略最大熵 actor–critic 方法；这里使用它作为优化工具，不提出新的通用 RL 算法。[R12](#ref-r12)

对技能 $k$：

$$
J(\theta_k)
=
\mathbb E\left[
\sum_{t=0}^{\tau_k-1}
\gamma^t
\big(r_t+\alpha\mathcal H(\pi_{\theta_k}(\cdot\mid h_t^\pi,g))\big)
+
\gamma^{\tau_k}R_{\mathrm{handoff}}
\right]
$$

$\tau_k$ 为恢复持续长度。$R_{\mathrm{handoff}}$ 必须来自固定后续策略的实际执行结果，而不是仅来自“力下降”或效果预测器自己的高分。

### 7.3 奖励结构

建议奖励由任务继续效果与有限的局部引导组成：

$$
r_t
=
w_p\Delta\operatorname{progress}_t
-w_\ell c^{\mathrm{load}}_t
-w_a\|a_t^{\mathrm{cmd}}\|^2
-w_j\|a_t^{\mathrm{cmd}}-a_{t-1}^{\mathrm{cmd}}\|^2
-w_t\Delta t
$$

$$
R_{\mathrm{handoff}}
=
w_{\mathrm{succ}}Y_{\mathrm{task}}
-w_{\mathrm{fail}}\mathbf 1_{\mathrm{hard\ failure}}
$$

进度可以在训练时使用仿真真值计算，但 actor 与运行时选择器不能读取该真值。比较方法必须使用相同奖励权限。

负载惩罚只有在力测量或估计可靠时才使用物理单位；否则使用明确命名的形变代理量。动作、时间与负载项用于抑制震荡、拖延和过载，但不能大到让“不动”优于合理尝试。

局部进度奖励不能简单设为“持续向插入方向移动”，否则策略可能不愿回撤。可以在失败恢复阶段降低此项权重，或以恢复后真正完成任务的奖励为主。任何奖励权重均需要消融与失败案例检查。

### 7.4 交还后的成功怎样归因给恢复动作？

这是训练闭环中必须明确处理的问题。

**主实现采用“交还处结果奖励”的有限时域恢复目标。** 每条样本包含恢复动作序列与固定后续策略执行；恢复交还后先跑完后续任务，获得 $Y_{\mathrm{task}}$ 与硬失败信息，再完成恢复片段的终端奖励写入。

对最后一个恢复动作 $t=\tau_k-1$，使用：

$$
r_{\mathrm{last}}^{\mathrm{train}}
=
r_{\mathrm{last}}+\gamma R_{\mathrm{handoff}}
$$

随后将恢复片段标为终端，不再从恢复 critic bootstrap。这与第 7.2 节的 $\gamma^{\tau_k}R_{\mathrm{handoff}}$ 一致。固定后续策略的动作不当作恢复 actor 样本，但其实际结果为恢复动作提供终端监督。

该目标关心在固定剩余预算内是否重新具备完成任务的能力；它不是对原任务所有后续时间步奖励的严格等价展开。后续阶段的实际耗时仍记录并纳入完整系统预算与代价评估。

若以后研究原任务的逐步折扣回报，可以把固定后续策略的实际折扣回报作为交还边界目标，但那是另一种目标定义，需要单独报告。第一版不混用两种处理，也不同时学习任意时刻的自主终止，而采用固定/规则交还机制。

### 7.5 非终端更新与模式边界

恢复仍在执行时，SAC 使用对应技能的双 $Q$ 目标：

$$
y_t
=
r_t+
\gamma
\left[
\min_{j=1,2}\bar Q_{j,k}(h_{t+1}^\pi,a')
-\alpha\log\pi_{\theta_k}(a'\mid h_{t+1}^\pi,g)
\right]
$$

其中 $a'$ 从相同技能策略采样。硬终止不 bootstrap；交还边界使用上节的实际结果奖励，不直接假定下一步仍由当前恢复技能行动。[R12](#ref-r12)

本文将明确的任务/恢复预算耗尽定义为该有限时域问题的结束，不从其后假想状态 bootstrap。若采样程序仅为存储而截断片段，但任务实际仍在继续，应保留非终端含义，两者不能混为一谈。

记录实际时间间隔。若一个接口调用包含不等长执行，应统一控制步长度，或以持续时间调整折扣，不能让一个长动作与一个短动作被当成相同时间成本。

### 7.6 冻结与交替更新

推荐轮次式训练：先冻结完整控制技能，包括控制历史编码器，收集效果标签并训练独立的结果表示与选择器；再在候选副本上训练技能头或控制适配层；最后刷新受影响的标签并验证。初始两个历史分支可从相同参数复制，随后独立更新。

不要在第一版同时持续更新基础策略、触觉编码器、效果预测器、所有技能与终止器，否则标签目标和状态分布都在变化，难以判断失败原因。

actor 与 critic 使用历史表示时，应采样连续序列，并用前缀重建循环状态。编码器更新后，旧缓存 embedding 可能失效；应保存原始观测或可重算的冻结前端特征，不直接长期复用过时的循环隐状态。

## 8. 运行时监测与技能选择

### 8.1 监测器的第一版不必复杂

采用可观测信号构造组合监测器，例如：基础策略持续发出推进意图，但视觉/本体进展很小；形变代理量持续上升；握持出现异常变化；触觉丢失与任务阶段不一致。

规则阈值可以用训练/验证数据确定，后续再学习异常概率。第一版不应让高层监测网络成为难以控制的额外创新变量。

建议设触发与退出两个阈值，并要求持续多个有效观测周期，同时限制最短模式停留时间，避免 NORMAL 与 RECOVERY 高频抖动。

不可用精确孔壁接触真值直接触发部署恢复，再声称系统仅靠触觉工作。真值监测器只能作为明确标注的上界或诊断对照。

### 8.2 选择准则

对处于数据覆盖范围内、满足硬限制的技能集合 $\mathcal A(H_t)$，定义：

$$
S_k
=
\hat p_k
-\lambda_c\hat c_k
-\lambda_u\hat u_k
-\lambda_\sigma\sigma_k
$$

$$
k^\star=\arg\max_{k\in\mathcal A(H_t)}S_k
$$

$\sigma_k$ 可以由小型模型集成的分歧估计。该不确定性只是一种启发式，不能视为严格置信区间或安全保证。只有一个网络时，可先用经验数据覆盖与验证校准替代复杂不确定性模块。

不要对未知技能打任意高分，也不要把选择器未尝试的组合视作失败。训练阶段可在安全允许的仿真范围内随机分配技能以改善覆盖；测试时使用冻结且预定的选择规则。

### 8.3 无可靠技能时怎么办？

部署执行中，若所有技能都不可靠、传感器失效或安全限制已触发，应停止当前尝试并记录。不能要求系统在每种状态都成功恢复。

仿真训练中，这些场景进入候选学习队列。探索只在重置/重放后的训练分支中进行，而不是让未经验证的策略直接替代正式技能。

### 8.4 区分三类失败

**选择错误：** 已有技能能够成功，但选择器选错。优先更新表示、效果预测和选择，不新增技能。

**能力不足：** 在合理覆盖的分支试验中，已有技能均表现不足。优先微调相关技能；仍不能覆盖时才扩展。

**观测不足或不可恢复：** 部署历史无法区分关键状态，或者当前预算与执行器能力不足。应改观测/历史、限制任务主张或承认失败，不能靠增加技能数掩盖。

分支评估中的 oracle 技能选择可帮助区分前两类，但它只能用于分析上界，不能作为正式测试方法。

# 第三部分：自进化闭环

<a id="section-9"></a>

## 9. 数据、分支标签与版本一致性

### 9.1 四类数据池

| 数据池 | 内容 | 主要用途 |
|---|---|---|
| $D_{\mathrm{demo}}$ | 基础示范与可选局部恢复示范 | 基础策略、技能暖启动 |
| $D_{\mathrm{rl}}$ | 恢复控制的连续交互片段 | actor–critic 训练 |
| $D_{\mathrm{out}}$ | 起点—技能—后续任务结果 | 效果预测、表示监督与校准 |
| $D_{\mathrm{anchor}}$ | 固定旧条件与新条件验证场景 | 接纳、回归测试与遗忘评估 |

训练分支、开发验证、接纳验证和最终测试应分开。用于方法调参与技能筛选的数据不能同时充当最终泛化证据。

### 9.2 失败状态从哪里来？

主要从冻结基础策略和当前正式系统的自主 rollout 中收集，同时使用受控扰动补充少见失败。记录异常触发前的历史，而不只保存已经严重卡死的瞬间。

对插入任务，可从正常接近轨迹中改变初始横向误差、姿态或抓取偏移。扰动应保持物理合法、无穿透，且保留现实中能够进入该状态的执行前缀。

同一父场景的相近帧、多个扰动复制及其所有分支应属于同一数据划分，防止训练与测试共享几乎相同的接触起点。

### 9.3 分支状态恢复的要求

应恢复或重建机器人关节、物体位置与速度、弹性状态、接触历史、控制器目标、传感参考、随机数状态及策略缓存等与后续行为相关的信息。

若仿真器不能提供完整状态快照，使用相同接近—抓取前缀重放，再经过固定稳定阶段。此时应称为“匹配起点试验”，而不是严格相同隐藏状态下的反事实试验。

复现起点后，先比较触觉、关节和物体可见状态的偏差；偏差超过容差时拒绝该匹配样本或将其作为新场景。不能只恢复刚体位姿就假定触觉状态一致。

### 9.4 控制分支成本与选择偏差

不对所有场景穷举所有技能。第一版可只在部分锚点上执行全部少量技能，其余场景以当前技能、最可能替代技能和少量随机技能形成稀疏标签。

用于校准的独立锚点应保持更均衡的技能分配，避免数据完全由旧选择器决定。保存技能分配规则，必要时在分析中区分主动采样分布与真实部署分布。

分支试验、失败重置、技能训练和候选验证都消耗资源，应纳入总交互与时间报告。分支能力也应允许相关强基线使用，否则无法区分数据优势与算法优势。

### 9.5 技能变化会让旧效果标签过时

某状态上旧版本技能失败，不意味着新版本仍然失败。因此，每条效果数据至少关联：

$$
(\text{scene\_id},\text{skill\_id},\text{skill\_version},
\text{base\_version},\text{continuation\_version},
\text{budget},\text{sensor\_config})
$$

第一版采用**轮次冻结协议**：

```text
轮次 r：
  冻结正式技能与后续策略
  -> 收集该版本的效果数据
  -> 训练/校准表示与选择器
  -> 训练一个候选技能副本
  -> 对候选刷新必要效果标签
  -> 验证完整候选系统
  -> 通过后进入轮次 r+1
```

旧的物理 transition 仍可能用于离策略训练，但旧的“该技能成功率”标签不能未经处理就当成新版本标签。优先重评共享锚点；预算不足时只使用版本兼容子集。第一版不依赖“把版本 ID 加进网络”来自动解决全部标签漂移。

### 9.6 技能扩展与表示漂移

增加技能后，效果向量会增加维度。可保留稳定技能身份，增加效果头，并在共享锚点上重新评估。保留少量冻结参考技能可为跨轮次效果比较提供稳定坐标，但不能据此假定所有任务都共享通用技能语义。

结果表示更新后，经验库中的 $z$ 必须重算或标记编码器版本。结果分支与控制分支分别维护版本；前者变化不应隐式改变正式技能动作。否则旧 embedding 与新 embedding 混合检索，距离不再可比。

## 10. 技能复用、更新与扩展

### 10.1 先复用，不立即扩展

对一批新失败场景，先执行有限技能评估，确认已有技能是否确实不足。选择器置信度低可能仅因为缺数据，不等于需要新技能。

若旧技能实际有效，更新效果预测与检索即可；若只有部分参数需要适应，在技能副本上微调；只有微调无法兼顾新旧条件或确有新的行为需求，才创建新技能头。

### 10.2 能力不足的操作性判据

对候选场景组 $\mathcal C$，可以监测：

$$
G(\mathcal C)
=
1-
\frac{1}{|\mathcal C|}
\sum_{i\in\mathcal C}
\max_k \tilde p_{ik}
$$

该指标仅在技能覆盖和试验量足够时有意义。未尝试技能较多时，先补足评估，不能把未知视为低成功率。

场景组可由效果空间的相似性与可观察历史共同形成，不必第一版就采用复杂聚类。仿真扰动标签可以用于实验分析，但若训练时直接用隐藏失败类型分配专家，必须向所有对应基线提供同样监督，并限制“自动发现”主张。

### 10.3 候选技能如何训练？

从最相关的旧技能复制参数，在目标场景组上 RL 微调，并混合旧条件 replay。候选不直接替代正式系统；其初始化、数据预算、训练步数与版本单独记录。

当多个候选都与现有技能效果高度一致、没有明显新覆盖时，优先不加入，避免技能库仅靠数量增长取得表面收益。

原始版保持少量技能和独立小型 head。自动拆分、合并与蒸馏可作为后续扩展，不需要同时纳入第一篇论文的核心。

### 10.4 接纳门控

候选必须比较**完整系统表现**，而不是只看候选在它自己收集的数据上的成功率。可采用：

$$
\operatorname{LCB}(\Delta\mathrm{SR}_{\mathrm{new}})>\delta
$$

$$
\operatorname{LCB}(\Delta\mathrm{SR}_{\mathrm{old}})>-\epsilon
$$

$$
\operatorname{UCB}(\Delta\mathrm{UnsafeRate})<\epsilon_u
$$

并检查资源增长是否值得。这里 LCB/UCB 是独立场景评估得到的统计界限示意，具体估计方法与阈值需在验证集确定；不是形式化安全证明。

小样本时不能声称严格非劣。更稳妥的是给出配对差值、置信区间与预先规定的接纳规则。反复用同一验证集筛选会过拟合，需限制候选次数、使用轮换场景，并保留从不参与接纳的最终测试集。

### 10.5 更新后真正发生了什么？

每轮输出一份变化记录：更新了哪些模块，新增或替换了哪个技能，覆盖了哪些新条件，旧能力是否退化，花费了多少交互，接纳或拒绝依据是什么。

只有记录这些变化，才能说明“系统积累了什么能力”。不能把技能数量增长本身当作进化效果。

### 10.6 主动触觉探测：可选而非主线必需

若观测确有歧义，可增加低幅度探测技能，如轻微回撤后再观察触觉变化。它的价值应通过“探测后的最终恢复收益减去时间与风险成本”评价，而不是直接奖励触觉变化或预测熵下降。

第一版先不加入主动探测，避免同时承担表示学习、技能扩展与信息动作学习三个困难问题。若完全无法从被动历史区分关键状态，再把它作为有明确必要性的扩展。

## 11. 完整训练与执行流程

### 11.1 阶段划分

| 阶段 | 固定内容 | 学习/采集内容 | 阶段产物 |
|---|---|---|---|
| A：平台与基础策略 | 任务、传感器、动作接口 | 基础策略训练或检查 | 可复现的正常轨迹与失败分布 |
| B：触觉残差基线 | 基础策略 | 微调模块与低维/图像输入对照 | 强接触控制基线 |
| C：初始恢复技能 | 基础策略、后续控制规则 | 少量恢复技能的 RL | 互补且可独立执行的技能 |
| D：效果表征 | 初始技能与后续策略 | 分支标签、效果预测、距离监督 | 固定库恢复选择系统 |
| E：持续适应 | 每轮正式系统快照 | 选择纠正、技能微调或扩展 | 经接纳验证的版本序列 |
| F：最终评估 | 全部参数与规则 | 只执行，不更新 | 泛化、持续学习与安全代价结果 |

阶段 B 可以先只做基线而不加入最小版本；论文比较时则必须保留，避免仅证明有恢复比完全没有恢复更好。

### 11.2 单回合执行伪代码

以下为算法伪代码，不是已实现的 UniVTAC 可运行接口。

```text
PROCEDURE EXECUTE_EPISODE(environment, deployed_system, budget):
    reset environment, policy caches, sensor references, history
    mode <- NORMAL
    recovery_count <- 0

    while task budget remains:
        obs <- read timestamp-aligned deployable observations
        history <- append obs and previous executed action

        if task is complete:
            log completion; return SUCCESS

        if hard stop or sensor/control invalidity:
            log reason; stop safely; return FAILURE_OR_INVALID

        if mode == NORMAL:
            if persistent anomaly(history):
                cancel cached base action chunk
                mode <- SELECT
            else:
                command <- base action plus optional bounded micro-correction
                execute_and_log(command)
                continue

        if mode == SELECT:
            scores <- evaluate compatible skills using history and remaining budget
            if no eligible skill or recovery_count reaches limit:
                log uncovered case; stop; return FAILURE
            selected_skill <- highest valid score
            recovery_count <- recovery_count + 1
            initialize selected skill state
            mode <- RECOVERY

        if mode == RECOVERY:
            if recovery budget exhausted:
                log recovery timeout; stop; return FAILURE
            if handoff conditions persist:
                mode <- RESUME
            else:
                command <- selected_skill(history)
                execute_and_log(command)
                continue

        if mode == RESUME:
            discard old base action chunk
            request fresh observation and fresh base prediction
            mode <- NORMAL

    log task timeout
    return FAILURE
```

连续控制期间不进行候选模型接纳。正式执行使用一致版本；训练与接纳在回合或批次边界进行。

### 11.3 效果数据采集伪代码

```text
PROCEDURE COLLECT_OUTCOMES(scene_batch, frozen_skill_bank, frozen_continuation):
    for each parent scene:
        choose a bounded subset of eligible skills
        for each chosen skill and repeat:
            restore full state or replay the validated prefix
            verify reconstructed starting observation
            save starting history, versions, goal, and remaining budget
            execute exactly one frozen recovery skill
            if handoff is allowed:
                run frozen continuation with further recovery disabled
            log task outcome, costs, violations, termination, and validity
    split data by parent scene, not by individual branch
```

### 11.4 持续适应伪代码

```text
PROCEDURE ADAPT(current_system, new_training_conditions):
    candidate_system <- copy current_system
    failures <- collect rollouts with current_system
    outcomes <- run bounded skill trials on selected failures

    if failures mostly come from wrong skill selection:
        update outcome representation and selector
    else:
        identify empirically uncovered but recoverable scene groups
        first fine-tune a copy of a relevant existing skill
        expand only if existing capacity cannot cover the new conditions
        refresh all labels affected by the candidate skill versions
        update outcome representation and selector

    rebuild embeddings for affected memory items
    evaluate candidate_system on new and old acceptance scenarios

    if predeclared acceptance criteria pass:
        deploy candidate_system at an episode boundary
    else:
        keep current_system

    preserve audit record and count all interaction costs
```

## 12. UniVTAC 接入方案

### 12.1 已核对的平台事实

以下信息依据 2026 年 9 月 17 日查阅的官方仓库与文档；实际实施时仍须锁定 commit。[R02](#ref-r02)

| 项目 | 当前公开说明 |
|---|---|
| 仿真基础 | Isaac Lab 与 TacEx 触觉仿真 |
| 版本分支 | `main` 对应 Isaac Sim 4.5；`isaac51` 对应 Isaac Sim 5.1 |
| 数据兼容性 | 两个仿真版本的任务数据不能直接互换 |
| 已公开 checkpoint | README 说明当前策略 checkpoint 关联 4.5 数据 |
| 传感器实施范围 | README 的 TODO 说明采集与评估目前支持 GelSight Mini |
| 可用起点 | ACT、ViTAL 等基线，以及 `insert_hole`、`insert_tube`、`insert_HDMI` 等任务 |

UniVTAC 提供触觉数据合成、编码器和操作基准，因此适合本方案的初始验证；但平台支持触觉任务，不意味着本文的 RL、状态快照和技能扩展接口已经存在。[R01](#ref-r01)

建议优先沿与已有 checkpoint 一致的环境建立可复现实验，不为追求吞吐在主实验中途更换仿真版本。若选择 5.1，应使用匹配的数据与模型训练流程。

### 12.2 官方执行接口与我们需要新增的内容

官方部署文档给出的 `task.take_action` 支持 `qpos`、`ee` 和 `delta_ee`：分别对应关节目标、末端位姿和末端增量。文档示例的 `qpos` 为 7 维机械臂加 1 维夹爪，`delta_ee` 为 3 维平移、3 维旋转和 1 维夹爪增量。[R03](#ref-r03)

但需要进一步检查一个调用内部执行多少仿真步、期间能否读取触觉与中断。如果 `take_action` 会阻塞地执行一段轨迹，就必须封装更短的控制步或加入中断机制，不能把“能给动作”直接当成“具有高频触觉反馈”。

建议新增的 RL wrapper 逻辑如下，接口名称是本方案设计，不是官方现成 API：

```text
reset(seed, condition)
    -> deployable_observation, metadata

step(control_command)
    -> next_deployable_observation
       reward
       terminated
       truncated
       info

capture_or_replay(scene_reference)
    -> matched_start_state, reconstruction_report
```

`info` 中可以包含训练奖励与离线分析所需真值，但必须与策略输入构造函数隔离。

### 12.3 默认数据采集不能替代失败经验采集

官方采集文档说明，管线保存成功回合，并自动跳过失败种子。[R04](#ref-r04)

因此必须新增 EvoTac 的 rollout logger，保存成功、失败、恢复超时、中断和执行器错误。需要记录异常前的历史与实际动作；否则恢复学习只有成功示范，没有足够失败上下文。

官方示范管线继续用于基础策略训练，失败与恢复经验由新的交互管线采集。不要通过关闭失败记录来提高数据文件的“平均质量”。

### 12.4 先验证物理可观测性

在训练复杂模型之前，对单个任务做受控检查：保持接近过程一致，分别改变横向偏差、旋转偏差、握持状态，观察触觉特征是否呈现稳定差异。

需要同时检查：信号相对噪声是否足够；左右指是否一致解释；变化是否只来自渲染背景；触觉差异能否支持区分不同有效纠正。

若某种摩擦或滑移现象没有被当前仿真可靠表达，不应把它设为主要论文任务。先研究可重复的接触几何与姿态变化，再决定是否扩展到材料或摩擦适应。

### 12.5 真值隔离

建议在代码中硬性划分：

```text
actor_observation:
    cameras
    tactile streams
    joint/gripper states
    executed-action history
    sensor validity and timestamps
    deployable task goal

training_info:
    exact object/fixture poses
    simulator contact forces or penetration diagnostics
    hidden friction and material parameters
    ground-truth progress and task completion
```

`training_info` 可用于训练奖励、评价与受控数据生成，不可绕过观测限制进入 actor、运行时监测器、技能选择器或恢复终止器。

第一版让 critic 也使用部署观测，简化归因。后续采用非对称 critic 时，明确标注特权信息，并向所有对应基线提供相同权限。

### 12.6 平台接入验收

进入大规模训练前必须能完成：基础策略复现；传感器时间对齐；一次动作内的观测与中断；失败回合保存；任务成功与硬停止区分；恢复后重新规划；同一场景可重复生成；真值输入单元测试。

完整状态快照不可用不是整个方向的否定条件，可改用匹配前缀重放。但应相应收紧“反事实比较”的表述，并把起点重建误差计入实验分析。

## 13. 网络结构与初始配置

### 13.1 建议的轻量实现

| 模块 | 第一版建议 | 说明 |
|---|---|---|
| 基础策略 | ACT 或已有视觉策略，冻结 | 不以训练大型 VLA 为前提 |
| 触觉前端 | 小型 CNN，或预训练编码器加投影层 | 先冻结大部分参数 |
| 双指特征 | 每指投影到 64—128 维 | 保留指身份与坐标约定 |
| 视觉特征 | 冻结视觉前端，投影到约 128 维 | 可以低频更新 |
| 时间融合 | 控制与结果分支各有一个小型 GRU，隐藏维度约 128 | 可共享冻结图像前端，时序参数独立 |
| 恢复效果表示 | 32—64 维 $z$ | 用于选择与经验组织 |
| 效果预测器 | 每技能成功率、代价、违规概率头 | 第一版不需要大模型 |
| 恢复 actor/critic | 小型 MLP 与少量技能头 | 读取独立控制历史，不读取正在更新的效果表示 |
| 初始技能数 | 2—3 个 | 先验证互补性，再考虑增加 |

以上维度只是起始配置，不能以“网络更大”替代等参数量的公平比较。预训练编码器对仿真触觉不适配时，应保留从头训练的小模型基线。

### 13.3 控制频率与预算如何设置？

可以先把接触控制目标设为约 20 Hz、基础策略重规划约 2—5 Hz，作为工程起点，而不是宣称平台已达到该吞吐。仿真物理步长使用经验证稳定的配置，不为了降低成本破坏接触动力学。

最终频率应由端到端延迟测量决定：采样、编码、决策与执行必须共同计时。无法实现快速触觉路径时，应报告真实频率并先验证离线选择能力，不把“理论推理快”写成“实际闭环快”。

恢复时长上限和动作幅度按任务尺度设定。插入任务可按孔隙尺寸、连接器长度和正常操作速度归一化，不跨所有任务使用同一毫米级阈值。

### 13.4 数据与显存

优先按回合保存压缩或 `uint8` 图像，以索引切历史窗口，避免将同一帧为多个窗口重复存储。循环网络训练需要连续片段及适当前缀，不宜随机抽孤立单帧。

前端冻结时可缓存特征；前端更新后必须失效重算。缓存需要包含编码器与预处理版本，否则训练数据在不同阶段不再具有相同含义。

每次正式实验保存源码 commit、任务资产、传感器参数、配置、随机种子、训练曲线、模型版本与评估场景清单。

## 14. 实验设计

### 14.1 任务设置

| 任务 | 建议研究的条件变化 | 核心问题 |
|---|---|---|
| Insert Hole | 横向偏差、角度误差、抓取姿态 | 能否选择正确恢复方向与方式？ |
| Insert Tube | 几何/接触阻力、不同初始接触 | 恢复技能能否复用于新条件？ |
| Insert HDMI | 方向性几何、朝向与抓取偏移 | 较复杂几何下是否仍有收益？ |

第一版固定机器人与传感器，先在单任务内跨条件，再做不同插入任务。不同任务之间的动作坐标、目标编码和技能适用性要明确对齐；不能仅因为它们都叫“插入”就假设技能能直接迁移。

随机化范围是待标定实验变量。可先以真实有效间隙 $c$ 归一化横向误差，从较小误差逐步增加；角度扰动也先从小范围开始。资产几何不支持的间隙修改、初始穿透和物理不可达状态不能作为主要测试分布。

### 14.2 训练、验证与测试划分

按物体/夹具资产、几何条件、扰动组合与父场景进行分组划分。时间相邻帧不能随机分到不同集合，同一父场景的多个恢复分支也不能跨集合泄漏。

需要区分三种测试：

**分布内测试：** 相同任务分布、全新种子与场景。

**组合泛化：** 各因素曾单独出现，但测试组合未出现。

**新条件适应：** 新几何或新接触条件到来，允许受限交互后再次评估；适应数据与评估场景分离。

零样本泛化和允许训练后的适应应分别报告，不能把后者称为零样本迁移。

### 14.3 强基线

| 编号 | 方法 | 要排除的解释 |
|---|---|---|
| B0 | 视觉基础策略 | 基础性能及失败空间 |
| B1 | 视觉—触觉直接融合 ACT | 收益是否仅来自多一种传感器 |
| B2 | 带历史的触觉残差 SAC | 收益是否只是普通接触 RL 纠偏 |
| B3 | 固定通用特征 + 固定恢复库 + 效果选择器 | 是否只需要多技能结构与成功率评分 |
| B4 | 联合效果预测，但无效果距离约束 | 新表示是否超出普通可供性学习 |
| B5 | 直接用预测效果向量检索，而非学习距离表示 | 学习 $z$ 是否真的有必要 |
| O1 | 固定恢复库 + 效果驱动表示与记忆 | 核心机制，不含结构扩展 |
| O2 | 完整持续适应系统 | 更新与扩展是否带来额外收益 |

B2 应参考 OmniTacTune 的触觉残差思想做强，并明确在本平台上属于机制复现，不与原论文不同任务的数字直接排名。[R05](#ref-r05)

表征实验首先共享完全相同的冻结技能权重，避免“表示更好”其实是“动作技能更强”。持续适应实验再允许各方法更新技能，并匹配交互预算、模型容量及梯度更新资源。

除了学习型选择器，应有随机选择或简单规则选择的诊断对照；但不能只用这些较弱方法支撑主要结论。

### 14.4 三个主实验

**实验一：触觉是否提供决策增量？**

构造视觉与本体观测近似、但接触历史不同的场景，比较视觉/本体历史与加入触觉后的效果预测和技能选择。关键不是分类准确率本身，而是不同选择是否带来实际恢复收益。

先确认无触觉模型不能仅凭物体 ID、固定位置或扰动标签完成判断。若本体信息已经足够解释全部收益，应收紧关于触觉必要性的主张。

**实验二：恢复效果表征是否支持复用？**

训练阶段固定技能集合，测试新的几何或抓取条件。比较 O1、B3、B4、B5 的选择质量、检索后经验利用率及目标条件学习曲线。

采用“效果距离损失开/关 × 效果驱动回放开/关”的分解实验，区分表征监督与采样策略的贡献。可再加入具备分支标签的 oracle 选择上界，用于测量剩余选择误差。

**实验三：持续适应是否必要且不遗忘？**

按阶段引入 $C_1,C_2,\ldots,C_J$。每一阶段只允许在当前训练条件和许可旧记忆上更新；随后在所有已见条件的独立场景上回测。

比较不更新、只更新选择器、固定容量技能微调、允许扩展，以及完整验证门控。新任务表现、旧任务保持、库规模与总成本必须同时报告。

### 14.5 关键消融

将消融集中在决定论文主张的部件，而不是堆叠大量无关网络变体：

| 消融 | 验证内容 |
|---|---|
| 去掉动作历史或时间历史 | 是否需要动态接触上下文 |
| 只用低维特征 / 只用图像 / 二者结合 | 高维触觉是否有必要 |
| 去掉效果距离约束 | 普通效果预测是否已足够 |
| 去掉效果驱动记忆检索 | 表示是否真正影响经验利用 |
| 以局部力下降替代后续任务标签 | “能继续任务”的定义是否重要 |
| 固定库、只微调、允许扩展 | 自适应的哪一层有效 |
| 不刷新旧标签 | 策略版本漂移的影响 |
| 不做旧条件验证 | 验证门控是否抑制遗忘 |

“不刷新标签”和“不做验证”等设置仅用于诊断，不应部署为正式版本。

### 14.6 公平预算与分支优势

总交互至少报告：

$$
N_{\mathrm{total}}
=
N_{\mathrm{rollout}}
+
N_{\mathrm{branch}}
+
N_{\mathrm{skill\ train}}
+
N_{\mathrm{accept}}
+
N_{\mathrm{reset/prefix}}
$$

上述项按互不重叠的实际执行步统计，不能把同一步重复计入多个项。另报 GPU 小时、墙钟时间、峰值显存和模型参数。

建议同时提供两类比较：固定同一批数据的算法比较，以及各方法自行采样但总预算匹配的系统比较。否则无法分辨算法收益、主动采样收益与额外交互收益。

最终测试的执行成本独立报告；它不能用于更新模型。失败后重置前缀的成本也应计入适应系统开销。

## 15. 指标与统计

### 15.1 主要指标

| 指标 | 定义与作用 |
|---|---|
| 总体任务成功率 | 从标准初始状态完整执行后的成功比例 |
| 条件恢复成功率 | 在统一失败起点集合上，一次恢复加固定后续策略的任务完成比例 |
| 局部交还率 | 恢复允许交回基础策略的比例；不等于恢复成功 |
| 无恢复完成率与恢复介入率 | 防止用过度触发掩盖基础执行能力 |
| 适应样本效率 | 成功率随累计交互步数的变化及曲线面积 |
| 恢复代价 | 恢复时间、动作总量、负载/形变代理量、违规率 |
| 选择质量 | 相对可评估 oracle 的成功率差、技能排序质量 |
| 效果预测质量 | Brier score、校准曲线、分布外性能 |
| 持续学习保持 | 旧条件成功率变化和遗忘 |
| 系统复杂度 | 技能数、参数量、内存与推理延迟 |

条件恢复成功率的分母不能由每种方法自己挑选“容易恢复”的状态。应使用公共失败集合，同时另外报告方法自身 rollout 中的恢复表现。

恢复失败、未触发恢复和因无可靠技能而停止，应在总体任务指标中得到一致处理。传感器/仿真基础设施异常单独报告，不能选择性剔除对某方法不利的回合。

### 15.2 遗忘度量

令 $A_{j,i}$ 表示学习至第 $j$ 个条件后，在旧条件 $i$ 上的独立测试成功率：

$$
F_J
=
\frac{1}{J-1}
\sum_{i=1}^{J-1}
\left[
\max_{j=i,\ldots,J-1}A_{j,i}
-
A_{J,i}
\right]
$$

同时报告完整成功率矩阵，避免单个平均数掩盖某类接触条件的严重退化。

### 15.3 统计设计

概念验证可先使用 3 个独立训练种子；主要结果建议扩大到至少 5 个，并根据效应大小与资源确定每个种子的独立测试场景数。这是实验设计建议，不保证自动获得统计显著性。

同一场景在不同方法间尽量配对；置信区间以训练种子和独立父场景为统计单位。不要把同一场景的多个时刻、多个分支当成完全独立样本。

单次二元成功标签可训练分类器，但不能精确估计某状态下的成功概率。效果距离监督应优先使用较可靠锚点，其余数据采用掩码监督。

用于效果选择的阈值、距离权重、接纳标准和随机化范围只在开发数据上确定。最终测试只运行冻结系统。

# 第五部分：落地与论文

<a id="section-16"></a>

## 16. 最小可行版本与实现顺序

### 16.1 最小版本应包含什么？

最小版本只做 `insert_hole`，固定机器人与 GelSight Mini，采用冻结视觉基础策略、短历史触觉编码、2—3 个恢复技能、一个效果预测器和明确的恢复状态机。

只允许一次恢复，不做主动探测，不自动增长技能头，不训练大模型。先回答：**相同的恢复技能集合下，触觉历史与效果监督能否让系统选得更好？**

### 16.2 按证据推进的里程碑

| 里程碑 | 必须产出的证据 | 未达到时怎么办 |
|---|---|---|
| M0：闭环可运行 | 触觉变化能在动作执行中改变后续命令 | 优先改控制接口，不训练复杂模型 |
| M1：触觉有增量 | 同等条件下，触觉改善恢复决策或接触控制 | 检查任务设计、信号或可辨识性 |
| M2：技能互补 | 不同技能在部分场景上有互补成功率 | 改课程或初始化，不急于学习选择器 |
| M3：效果选择有效 | 比随机/规则/普通特征选择更好 | 检查标签、样本覆盖和状态重建 |
| M4：表示与复用有效 | 比仅效果预测、直接效果向量检索有额外收益 | 收紧贡献，不强行宣称新表征 |
| M5：持续适应有效 | 新条件提升，旧条件保持，成本可接受 | 先固定库或只更新选择器 |
| M6：跨任务证据 | 在其他插入任务重复主要趋势 | 限定为单任务接触适应结论 |

每个里程碑都以可观察结果为判断标准，而不是以完成多少模块为标准。

### 16.3 初始数据规模怎样控制？

先用少量独立失败起点检查流程，再扩大。示例：30 个起点、3 个技能、每组合 2 次试验，共 180 个分支，用于检查标签与行为互补；这通常不足以支持精细成功概率或泛化结论。

效果距离的概念验证可在较小的高覆盖锚点子集上增加重复，而不是马上扩大技能数。正式规模由标签噪声、场景多样性和仿真成本决定，不能把上述数字当成论文充分样本量。

### 16.4 第一篇论文建议保留的范围

推荐保留“效果驱动触觉表示与经验复用 + 固定库/有限扩展的持续适应”。先证明这一条主线，不同时加入语言规划、复杂主动感知、多机器人、多传感器、世界模型和完整无监督技能发现。

这不是否定后续扩展，而是保证每个模块都能对应明确研究问题与对照。

<a id="section-17"></a>

## 17. 风险、失败解释与替代方案

| 风险 | 可能原因 | 优先处理 |
|---|---|---|
| 触觉没有明显帮助 | 任务可由视觉/本体解决，或触觉变化不可信 | 做可观测性检查，重新设计接触歧义 |
| 恢复技能都相同 | 相同初始化、课程和奖励导致塌缩 | 增加互补训练起点，检查行为而非只看名字 |
| 效果表示无收益 | 多头效果预测已足够，距离监督噪声大 | 保留诚实消融，简化或转向采样机制贡献 |
| 检索相似却动作失效 | 几何/坐标细节被压缩或跨任务不兼容 | actor 保留完整历史，限制跨任务对齐范围 |
| 新技能变好，旧能力变差 | 共享编码器漂移、数据分布偏置 | 冻结前端、小型适配器、旧数据回放与接纳验证 |
| 标签突然不一致 | 技能或后续策略更新，预算改变 | 版本隔离，刷新锚点与效果头 |
| 奖励学出不动或乱退 | 时间、力惩罚和终端奖励失衡 | 以真实任务继续效果为主，检查动作轨迹 |
| 起点无法严格复现 | 弹性与控制器状态未完整恢复 | 使用匹配前缀重放，记录重建偏差 |
| 仿真过慢 | 触觉渲染、软体接触与重置开销高 | 先低维特征与单任务，分层采样，缓存冻结特征 |
| 自动扩展没有收益 | 更新已有技能已经足够 | 采用固定容量持续适应，不强行保留扩展 |
| 极端状态不可恢复 | 已丢失物体、预算不足或硬件约束 | 正确停止并纳入失败统计，不无限重试 |

### 17.1 什么结论现在不能写？

不能写“首次提出触觉强化学习恢复”“保证安全”“保证不遗忘”“无需真实数据即可直接迁移任意传感器”“从任意失败中恢复”“已经证明优于所有现有方法”。

不能把新名字、新损失项或更复杂流程自动当成创新。研究价值取决于它是否带来清晰、可重复且公平的增益。

### 17.2 什么情况下需要改变方向？

若在多种受控接触变化下，触觉历史始终无法支持优于无触觉的恢复决策，应首先检查传感器与任务，而不是继续增加网络规模。

若触觉确实有用，但效果距离不优于简单成功率预测，可以保留学习型恢复闭环，将贡献收敛为更明确的持续适应或预算受限数据采样问题。

若固定库微调已覆盖所有新条件，无需为了“自进化”叙事强行增加技能。此时可以研究何时不应扩展，以及固定容量下的适应效率。

## 18. 论文组织与贡献表述

### 18.1 推荐论文叙事

背景不应只写“视觉无法感知接触，因此加入触觉”。更有针对性的逻辑是：

**接触丰富任务中的失败，不仅要求感知异常，还要求选择正确恢复；而触觉外观相似性并不直接对应恢复行为的有效性。我们研究能否以恢复后任务继续的真实结果组织触觉经验，并通过复用与经验证更新应对接触条件变化。**

已有研究为触觉残差、技能可供性与失败驱动学习提供了基础；本研究要证明的是其中更具体的表示与适应机制。[R05](#ref-r05)[R10](#ref-r10)[R13](#ref-r13)

### 18.2 可用的贡献草案

**贡献一：** 提出一种面向接触恢复决策的触觉—动作历史学习方法，以固定恢复技能的真实下游效果监督表示，并研究其对技能选择与经验复用的作用。

**贡献二：** 设计一个能力不足驱动的持续适应流程，区分选择错误与控制能力不足，并通过版本一致的标签刷新和新旧条件验证更新技能。

**贡献三：** 在可控接触条件变化下建立系统评估，报告总体成功、条件恢复、适应成本、旧能力保持和触觉信息利用，并与触觉残差 RL、普通技能效果预测和固定容量方法比较。

正式论文根据实际实现调整措辞。若未实现技能扩展，删除相关贡献；若距离监督无显著增益，不把它保留为核心结论。

### 18.3 建议的论文章节

Introduction 说明接触歧义与恢复经验复用问题；Related Work 区分触觉策略、残差 RL、恢复与技能可供性、持续学习；Method 按观测、效果表征、连续技能和适应闭环展开；Experiments 对应三个研究问题；Limitations 讨论传感可辨识性、标签预算、版本漂移和仿真范围。

建议的方法图突出三个信息流：**实时观测到动作、恢复试验到效果监督、验证结果到技能更新**。颜色和箭头不应掩盖训练真值与部署输入的边界。

### 18.4 当前方法的最终定位

> EvoTac 不是“触觉 + 强化学习 + 技能库”的简单组合。当前拟验证的主张是：以恢复后任务继续的效果为依据组织触觉经验，可以比外观相似性或普通效果预测更有效地复用接触技能；再以能力不足和独立验证驱动更新，实现受控的持续适应。

这句话同时规定了研究目标和证伪条件：如果没有超出强基线的复用与适应收益，就不能仅凭系统复杂度宣称方法成立。

# 附录 C：可复现与逻辑检查

## C.1 开始训练之前

确认固定仿真版本与任务资产；传感器数据确实可读；参考图像来自正确阶段；各动作单位与坐标一致；执行中断有效；异常前历史可保存；部署输入不含隐藏真值。

先用同一组场景检查不同恢复动作的行为差异，并测量完整闭环延迟，而不只测神经网络前向时间。

## C.2 效果学习之前

确认后续策略、技能版本和预算固定；一次标签试验只有一次恢复；未知标签有掩码；无效仿真试验与动作导致的失败分开；所有同源分支在同一数据划分；表示监督具有足够技能覆盖。

效果标签使用实际运行结果，不用同一个选择器自己的高分代替成功证据。

## C.3 每次接纳候选之前

刷新受影响标签；重建变化后的 embedding；对完整系统做新旧条件配对评估；计入训练、分支、重置和验证成本；确认无明显违规增长；保存拒绝与接纳记录。

共享编码器更新也属于完整系统变化，不能只验证新技能头。

## C.4 撰写论文之前

区分已验证与待验证内容；清楚说明预印本文献；限定传感器和任务范围；不给不同任务的论文结果直接排名；不把一次成功演示当成泛化证据；不以总成功率掩盖过度恢复或旧能力退化。

最重要的审查问题是：**去掉效果驱动表示或记忆机制、保留相同数据和强恢复技能后，结论是否仍然成立？** 如果答案是肯定的，应重新收敛创新表述。
