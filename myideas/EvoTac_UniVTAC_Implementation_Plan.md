# EvoTac 在 UniVTAC 中的多阶段实现与可行性验证计划

**日期：** 2026-09-17
**依据：** [EvoTac 方法方案](EvoTac_Method_and_UniVTAC_Plan.md)、[阶段 1 详细计划](EvoTac_Phase1_Implementation_Plan.md)、[已有数据分析](../evotac/docs/Isaac51_Existing_Data_Assessment.md)及当前仓库源码。
**范围：** 单任务完整闭环；核心方法实现与必要验证。
**状态：** 已完成现有任务数据的结构审计、接触数据盘点及编码器源码检查；控制接口、权重加载、训练和 GPU 集成尚未完成。

## 一、目标与实施约定

在 `insert_hole` 单任务中完整实现：

**冻结视觉策略 → 触觉历史感知 → RL 恢复技能 → 恢复效果表征与选择 → 经验复用 → 持续适应与有限技能扩展。**

重点回答三个问题：

1. 触觉历史能否提高恢复决策和最终任务成功率？
2. 恢复效果监督能否比普通成功率预测更有效地组织经验、支持复用？
3. 持续适应能否改善新条件表现，同时保持旧能力？

实施约定：

- 使用当前仓库对应的 Isaac Sim 5.1、Isaac Lab 2.3 与本地修改版 TacEx，锁定源码、资产和环境版本。
- 固定现有机器人、GelSight Mini 和 `taxim` 后端；不修改触觉后端。
- 基础策略采用视觉 ACT，优先复用本地 `data/isaac51/insert_hole` 成功示范，经时间配对和控制兼容性验证后训练并冻结；按验证结果补采，不默认重采全部示范。4.5 策略权重仅作为候选初始化，不直接视为 5.1 可部署策略。
- 触觉图像前端优先验证公开 `encoder.pth`，通过后使用共享 ResNet18；必要时利用已有 `data/contact` 适配。控制历史和效果历史网络仍独立训练，公开编码器不等于 EvoTac 效果表征。
- 新增代码、配置、数据、模型、日志和仿真 workspace 全部位于 `evotac/`。原数据只读引用；通过独立入口和任务子类扩展，不改原任务、ACT、编码器训练脚本或 TacEx。
- 初始训练三个恢复技能；整个验证期间技能库最多增加一个技能。
- 每回合最多一次恢复；恢复后的后续策略固定为视觉 ACT。
- 不加入世界模型、语言规划、主动探测、多机器人或跨任务迁移。
- 不安排独立的大规模调试、性能优化或无关网络消融阶段。必要正确性检查并入实现验收，研究实验集中到阶段六；阶段间复用已有结果，不重复采样。
- 文中的样本规模、频率和阈值是实施默认值，不是已验证的最优配置或性能保证。

|---|---|---|

| ACT 自主失败、受控偏差和短局部恢复示范 | 基础 ACT 冻结后采集，阶段 1 只需少量脚本验证样例 | 阶段 2/3：监测、暖启动与恢复 SAC |

| 匹配起点的多技能结果 | 冻结技能后分支试验；复用阶段 3 中版本一致的验收结果 | 阶段 4：效果监督 |
| 新条件、接纳与旧条件回归数据 | 按独立父场景划分，在适应轮次中采集 | 阶段 5/6：更新与评估 |

现有成功数据缺少独立执行命令、完整抓取前缀、两类参考、逐模态时间及恢复标签，不能直接作为 SAC transition 或恢复效果标签。阶段 1 不以完成后续所有数据采集为验收条件。

### 训练依赖与冻结边界

```text
阶段 1：固定周期接口、同步观测、记录器、匹配起点重放
    ↓
阶段 2：已有示范 → 视觉 ACT → 5.1 闭环验证 → 冻结基础策略
         公开编码器 → 加载/预处理验证 → 固定图像前端候选
    ↓
阶段 3：新局部示范 → 暖启动控制历史网络 → 冻结共享控制表示
         新恢复交互 → SAC actor/critic → 冻结技能及交还机制
    ↓
阶段 4：固定技能分支结果 → 效果历史网络/embedding/选择器
    ↓
阶段 5/6：新失败 → 更新候选 → 标签刷新 → 独立验证/接纳/最终评估
```

阶段 2 的恢复状态机先用脚本动作验证，学习型技能在阶段 3 替换。若图像前端必须适配，最迟在阶段 3 的技能正式训练前完成，并与控制历史编码器一起冻结；不能在采集效果标签时继续改变控制表示。

## 二、分阶段实现

### 阶段一：实现可中断控制、观测与经验采集

**目标：提供能够真实执行触觉闭环的 UniVTAC 接口。**

#### 核心实现

1. 新增 EvoTac 环境包装器，提供以下接口：

   | 接口 | 职责 |
   |---|---|
   | `reset(seed, condition)` | 生成指定条件，返回部署观测与场景元数据 |
   | `step(action)` | 执行固定时长控制步，返回观测、奖励、终止/截断标志和训练信息 |
   | `replay_start(scene_ref)` | 重放接近和抓取前缀，返回匹配恢复起点与重建误差 |
   | `close()` | 刷新记录并释放环境、视频等资源 |

2. 保留 ACT 的八维关节目标语义。恢复采用七维归一化动作：世界系平移、世界系旋转向量和夹爪关节位置增量，通过局部微分 IK 转换为目标。控制点为 `panda_hand`，位姿与 Jacobian 坐标/索引一致；尺度、限位和每步变化限制写入 YAML。
3. 不直接将现有 `take_action(delta_ee)` 当作 RL 单步，因为它会执行规划轨迹。在 `evotac/envs/` 中新增固定时长入口，复用已有 `_step/_configured_decimation`，不改共享基类。控制和接触前缀显式 `force=False`，固定 PD 参数；IK 或执行失败显式结束尝试，记录实际物理步数。完整 reset 后重新采样观测，不转发初始化早期的返回值。
4. 物理频率保持 120 Hz，控制频率设为仿真时间 20 Hz，每步推进六个物理步，并完成渲染/传感器同步。基础策略示范按相同控制时间轴处理，避免训练与执行动作时序不一致。实际墙钟吞吐单独记录。
5. 部署输入仅包括相机、双指触觉、关节/末端状态、执行命令历史、有效性和时间戳。物体真值、隐藏扰动和任务进度放入独立 `training_info`，不进入 actor、critic、监测器、选择器或交还规则。
6. 实现独立 rollout 记录器，保留成功、失败、超时、停止和执行异常。区分原始动作、限幅后命令、实际接受命令与实测状态变化；critic 的 action 与 actor 输出及执行适配器定义一致，不能用实测位移替代动作。
7. 恢复起点采用“同种子＋相同执行前缀＋固定稳定过程”重建，恢复参考图、历史及策略缓存。不能假设刚体位姿恢复等价于完整触觉状态恢复。
8. 按实际物理步维护任务总预算与恢复预算，不以可能包含不同执行时长的 API 调用次数比较方法。
9. 建立旧示范、接触预训练和新 rollout 的来源清单及不同数据契约，禁止混入同一个恢复 replay buffer。阶段 1 完成旧数据转换设计和少量兼容性检查，不以下载编码器或训练模型作为控制接口的前置条件。具体实现顺序见 [阶段 1 详细计划](EvoTac_Phase1_Implementation_Plan.md)。

#### 必要验收

一次短集成运行同时确认：控制步时长正确、观测不包含未来帧、真值不进入策略、失败轨迹能保存、重建起点误差有记录。

重建容差由开发集重复前缀重放的误差分布确定并冻结。超容差试验标为无效匹配，不作为技能失败标签；分别记录触觉、本体和物体状态误差，后者只用于离线检查。

**阶段产物：** 可训练环境、统一观测/动作契约、失败与恢复数据管线、已有资源清单与旧数据兼容性报告。正常步为六个物理步，中断首先保证控制周期边界；不声称实现墙钟实时急停。

### 阶段二：实现基础策略、触觉历史与恢复状态机

**目标：形成可执行的正常控制和恢复切换系统。**

#### 核心实现

1. 优先用已有 100 条 `insert_hole` 示范训练视觉 ACT，按独立父场景划分训练/开发/留出集（例如 80/10/10），归一化只使用训练集。先确认源频率，再对齐 20 Hz 的观测—目标时间及 9→8 维关节映射，验证 `force=False` 下执行兼容性；不兼容时仅作暖启动并补采新控制数据。公开 4.5 视觉 checkpoint 作为可选初始化，不能把 4.5 统计量直接作为新数据的归一化参数。ACT 闭环验证后冻结权重、统计量和时序；明确关闭触觉输入。
2. 在抓取前采集空载触觉参考，在稳定持握且未接触外部目标时采集抓取参考。参考采集挂接到任务相应阶段，异常期间禁止更新。
3. 输入原始触觉、两类参考差分、接触面积/中心/左右差异等图像代理特征；缺失参考用掩码表示，不伪造可靠零差分。形变代理不称为已测得的三维力。
4. 使用长度为 8 的历史窗口、128 维 GRU 和 64 维效果 embedding。历史同时保留采样间隔、视觉帧年龄、有效性和上一执行动作；不以未来帧补齐过去观测。
5. 图像前端优先采用通过加载验证的共享 ResNet18，单指带标记点原图编码为 512 维，并保留左右身份。第一版将参考差分的面积、中心、左右差异等低维线索单独输入历史网络；不把三通道权重直接套到九通道拼接图像，也不把有符号差分当原图归一化。控制历史编码器与效果历史编码器独立维护，效果训练不得改变控制分支；参考/差分原图仍保存，后续若增加差分图像分支须单独暖启动并版本化。
6. 实现状态机：`NORMAL → SELECT → RECOVERY → HANDOFF → NORMAL`，另设 `STOP`。
7. 异常监测使用推进意图、实际运动进展、触觉相对变化和接触丢失。触发与退出阈值由开发数据确定，连续三个有效周期满足条件才切换；设置最短模式停留时间。
8. 进入恢复时清除 ACT 待执行动作和时间聚合缓存；交还时重新获取观测并重新规划。
9. 交还采用固定规则：最短恢复时间后，异常解除并连续三个周期稳定。恢复超时视为失败；后续 ACT 不触发第二次恢复。无可靠技能、传感器持续失效或硬限制触发时进入停止状态。

#### 旧示范转换与编码器接入要求

- 保存帧步号间隔均为 2，与当前 120 Hz 物理/60 Hz 保存配置一致，但原文件没有频率快照，源频率仍须确认。若确认为 60 Hz，20 Hz 候选标签为 `o[i], q[i] → q[i+3]`，`i=0,3,6,…`；原 `downsample_factor=3` 仍以 `q[i+1]` 为标签，不能直接复用。该标签是未来测得状态的模仿代理目标，不能当成原始接受命令。ACT chunk 长度按仿真秒数重新确定。
- 在 `evotac/data/` 编写独立转换，适配源目录、相机命名和关节顺序，不改原预处理器或全局 `SIM_TASK_CONFIGS.json`；原图和 actor 真值按白名单分离。旧首帧不能冒充空载/抓取参考；没有逐模态时间的旧文件也不能补造已验证的时间戳。
- `encoder/network.py` 当前预训练结构为 ResNet18 + 512 维 latent，可通过解码头监督 RGB、带标记图、深度、标记点和相对位姿，加权 MSE；它提供单帧接触表征，不含动作历史、恢复奖励或效果距离监督。预训练真值仅作训练目标，部署编码器只输入允许的图像。
- 先下载/登记 `encoder.pth` 的来源 revision、哈希和配置，检查参数键与形状、BatchNorm 版本、输入通道/尺寸/范围、颜色约定及单指输出，再用旧任务图像和新 wrapper 图像验证有限值、非恒定输出及确定性。官方权重实际监督配置尚未核实，不仅凭当前训练脚本猜定。
- 若只导入 backbone，应显式匹配并完整核对 backbone 参数，解码头的舍弃单独记录；不得用无检查的 `strict=False` 掩盖不兼容。路径缺失或关键参数未加载必须报错，不能沿用原 ACT “文件不存在就跳过加载”的行为。冻结要同时设置 `requires_grad=False` 和 `eval()`，并检查参数及 BatchNorm 缓冲区不变化。
- 公开权重通过则优先冻结使用，无须先重训整个编码器。适配不足时只使用已有 contact 训练划分做微调/预训练：修正旧 `contact-gs` 路径、`stream_to_img` 参数不匹配、尺寸/深度归一化假设及损失统计；同一轨迹所有帧和双指必须在同一划分，避免沿用逐帧随机划分。解码器监督只用于训练，原脚本留存，修正在 `evotac/` 适配层完成。
- 仅在公开编码器不兼容且适配不能解决时退回小型 CNN，在局部示范暖启动中训练并于 SAC 正式训练前冻结。所用初始化、适配数据和成本需固定并向对应触觉基线保持一致；不用最终测试集选择前端。

#### 必要验收

在开发场景先验证视觉 ACT 能闭环执行，再在一个可重建失败场景中完成“触发—暂停—脚本恢复动作—交还—重新规划”，确认旧 ACT 动作不会继续执行。同时留存编码器加载覆盖、预处理版本及冻结检查报告。复用阶段一 smoke 入口扩展验收，不将阶段一是否通过依赖于尚未训练的 ACT。

**阶段产物：** 冻结基础策略、已验证的图像前端及预处理、触觉历史模块与运行时闭环。历史模块的结构在此就绪，控制历史表示在阶段三暖启动，效果历史表示在阶段四训练。

### 阶段三：训练互补的连续恢复技能

**目标：获得真正依赖反馈的学习型技能。**

#### 核心实现

1. 初始化三个技能：回撤后重新接近、横向位置调整、姿态调整。
2. 用短局部示范提供行为偏置，再由 SAC 学习动作方向、幅度和时序。三个技能使用相同动作空间，名称不限制最终动作，脚本仅用于暖启动。
3. 控制历史主干先通过局部示范暖启动并冻结；前端默认沿用已验证的冻结编码器，如需适配须在此冻结点之前完成。每个技能训练独立 actor 与双 critic，恢复历史来自新契约交互；不把旧关节状态序列伪造为七维恢复动作。后续适应优先更新技能头。
4. 从冻结 ACT 自主失败及物理执行产生的受控偏差中采样起点，不通过接触中瞬移物体制造训练状态。各技能使用有差异的课程起点并共享公平的奖励权限。
5. 默认配置：`discount=0.99`、actor/critic 学习率 `3e-4`、序列 batch size 16、更新/采样比 1。连续片段保留历史前缀，避免将孤立帧当作完整循环状态。
6. 奖励以恢复后 ACT 能否完成任务为主，辅以动作、时间、震荡和形变代理惩罚。局部引导不得持续奖励向下推进而阻止必要回撤。
7. 恢复交还后运行固定 ACT，取得最终结果，再写入最后一个恢复 transition：`r_last ← r_last + γR_task`。该边界不 bootstrap，ACT 后续动作不写入恢复 actor 的训练样本。
8. 任务成功沿用环境判定；物体丢失、控制失败、恢复预算耗尽分别记录，不以局部形变下降代替任务成功。真实预算耗尽不 bootstrap，纯存储截断保留非终端语义。

#### 必要验收

在同一公共失败集合上分别执行三个技能，获得起点—技能结果矩阵。至少两个技能应在不同子集上具有优势，且技能库 oracle 表现高于最佳单技能，否则尚不具备验证技能选择的前提。

仅将最终冻结技能和后续策略版本一致的验收矩阵复用为阶段四效果数据，训练中较早版本的结果不混作当前标签。Oracle 仅是离线分析上界，不进入正式部署决策。

**阶段产物：** 三个冻结 RL 技能、连续交互数据和技能互补结果。

### 阶段四：实现效果表征、选择器与经验复用

**目标：完整实现 EvoTac 的核心方法。**

#### 核心实现

1. 冻结技能、控制编码器、后续 ACT 和交还规则，采集带版本的效果标签。
2. 起始训练规模为 120 个独立父场景：40 个锚点执行全部三个技能，每组合五次有效试验；其余 80 个场景各随机分配两个技能，各执行一次，共 760 次有效分支试验。该规模是初始数据预算，不保证足够估计精细成功概率。
3. 重复试验使用预先规定的微扰种子，各技能和各方法共享协议。微扰发生时刻与分布固定，不重复完全确定性的同一轨迹来虚增样本；统计目标是该匹配起点协议下的结果。
4. 每条标签包含最终任务成功、局部交还、恢复代价、违规、有效性，以及技能/基础策略/后续策略/编码器版本、传感器配置和剩余预算。
5. 实现多头效果预测：输入 `z、任务目标、剩余预算`，输出各技能成功概率、代价和违规概率；效果头不得绕过 `z` 直接读取完整历史。
6. 按原方案第 6 节实现 `L_repr = L_out + λ_metric L_metric`。`L_out` 使用带掩码的成功/违规 BCE 和代价 Huber；距离目标来自真实重复试验的平滑成功率、归一化代价与违规统计，使用原方案的归一化平方距离和 Huber 约束。
7. 只对版本兼容、有共同技能可靠标签的状态对启用距离监督；可靠性权重来自有效试验量。未试验组合保持缺失掩码，基础设施异常与真实动作失败分开，不使用当前预测生成自身的效果距离标签。
8. 选择器按成功概率减去代价和违规惩罚排序；覆盖不足或全部低于开发集阈值时停止当前尝试，并进入后续训练队列。第一版使用单模型、开发集校准与经验覆盖，不增加模型集成。
9. 建立版本化记忆库。对新条件按 `z` 检索最近的 20 个兼容父场景，用于技能初始化选择和旧经验回放。兼容场景不足时使用全部可用场景，不复制样本伪造覆盖。
10. 适应训练 batch 默认由 50% 当前条件、25% 检索旧经验和 25% 均匀旧经验组成，保留失败反例。表示更新后重算索引；缓存冻结前端特征而非长期复用过时循环隐状态。

#### 必要验收

在共享冻结技能条件下，与相同网络、相同数据、仅使用 `L_out` 的模型比较选择和恢复结果。确认控制分支参数未变化。完整统计比较统一纳入阶段六，不为该验收重复建立测试集。

**阶段产物：** 固定技能库 EvoTac、效果监督数据、可用于适应的经验记忆。

### 阶段五：实现持续适应与有限技能扩展

**目标：实现利用自身失败改进能力、验证后接纳的完整闭环。**

#### 核心实现

1. 依次引入三类条件：`C1` 为横向接近误差；`C2` 新增角度误差；`C3` 新增抓取偏移并与前两类误差组合。
2. 保持原有资产几何，扰动通过抓取和接近动作执行。使用有效间隙和正常持握尺度归一化参数，范围只在开发阶段确定并冻结；隐藏条件标签仅用于场景生成与结果分析。
3. 每轮先对新失败组补足已有技能的实际分支结果：已有技能有效但选错时仅更新效果分支和选择器；已有技能不足时复制最相关技能并用 SAC 微调；替换无法兼顾新旧条件时尝试保留旧技能并增加候选头。
4. 未覆盖技能应先补评，不能把未知当作能力不足。确认观测不足或预算内不可恢复的场景单独统计，不通过扩展技能掩盖。
5. 每个条件阶段最多评估两个候选方案，技能总数最多四个。候选训练结束前不替代正式版本。
6. 更新技能后刷新其效果标签；扩展技能后增加效果头并补充共享锚点标签。旧版本效果标签不得直接作为新版本监督；旧物理 transition 仅在动作/观测契约兼容时用于离策略训练。
7. 在独立接纳场景上比较完整系统。默认接纳条件：新条件成功率配对差值的 95% 置信区间下界大于 0；旧条件平均差值下界不低于 −5 个百分点；违规率增量上界不超过 2 个百分点。
8. 未通过则保留旧系统。候选使用互不重叠的接纳场景，最终测试集始终不参与筛选。样本不足以满足区间规则时记录证据不足，不自动放宽阈值。
9. 保存每轮接纳/拒绝原因、版本变化、技能数和完整交互成本。替换或增加候选须连同更新后的选择器一起验证。

#### 必要验收

完成一轮真实的“新失败采集—更新—标签刷新—候选比较—接纳或拒绝”。未发生有效技能扩展时只报告持续适应，不宣称已验证技能自扩展。

**阶段产物：** 可执行适应流程、版本序列、接纳记录和新旧条件表现矩阵。

### 阶段六：完成最少但充分的可行性实验

**目标：用三组实验对应三个研究问题，避免大量无关测试。**

| 实验 | 必须比较的方法 | 判断内容 |
|---|---|---|
| 触觉与恢复是否有效 | 视觉 ACT、带历史触觉残差 SAC、EvoTac、去掉触觉的 EvoTac | 触觉是否提供额外收益，完整恢复是否优于普通残差纠偏 |
| 效果表征与复用是否有效 | 完整方法、去掉距离损失、关闭效果检索、两者均关闭、直接预测效果向量检索 | 表示监督和记忆组织是否分别有效 |
| 持续适应是否有效 | 不更新、仅更新选择器、固定容量微调、允许有限扩展 | 新条件收益、旧能力保持和扩展必要性 |

执行约定：

- 残差 SAC 是同平台机制基线，使用相同冻结 ACT、观测权限和预算，不能将不同动作空间的数值直接相加。残差经适配器在统一控制空间融合后执行。
- 无触觉对照同时移除触觉图像、差分和触觉派生代理量，其余历史、技能和预算保持一致。
- 表征与选择实验共享完全相同的冻结技能；适应实验再允许更新控制参数。关闭效果检索时，将对应采样份额改为均匀旧经验，保持新旧数据比例不变。
- 直接效果向量检索对照使用预测的各技能效果作为检索表示，其他学习、回放和预算规则保持一致。
- 使用三个独立训练种子。最终每类条件至少 100 个独立父场景，各方法使用配对场景；不把多个分支当成独立父场景。
- 同一父场景的历史、扰动副本和全部分支只能属于同一数据划分。训练、开发、接纳和最终测试分别隔离，最终测试期间不更新模型。
- 接触预训练也按来源轨迹隔离双指与全部帧；记录预训练/暖启动数据和计算成本，相关触觉基线共享同一前端初始化与权限。已有 100 条成功示范的留出集只用于模仿学习检查，不替代未筛选的正式测试场景。
- 使用公共失败集合评估条件恢复成功率，同时从标准初始状态评估总体成功率。方法未触发、拒绝恢复和停止均保留在相应分母中。
- 正式评估使用独立场景清单，避免现有评估脚本中的专家筛选与失败种子缓存改变各方法分母。基础设施异常单独报告，按预先固定的统一重试规则处理。
- 交互预算按实际物理步互斥统计，包括前缀重放、分支试验、技能训练和候选接纳。各方法采用相同总预算和预定梯度更新上限；最终测试成本另报。
- 报告总体/恢复成功率、适应曲线及曲线面积、旧条件保持矩阵、违规率、技能数量和墙钟成本；效果预测附报 Brier score，选择附报距技能 oracle 的差值。
- 置信区间按训练种子与父场景分层计算。三种子是概念验证配置，不能把区间结果解释为广泛泛化保证。
- 保存配置、种子、后端、版本、命令和结果。仅修改后端时才需要额外验证 `taxim` 与 `pix2pix`；本计划不安排跨后端实验。

## 三、工程组织与接口变更

| 位置 | 实施内容 |
|---|---|
| `evotac/envs/` | wrapper、固定周期执行器、动作/观测契约、前缀重放；复用底层 `_step`，不改共享基类 |
| `evotac/envs/tasks/insert_hole.py` | 专用任务子类：条件扰动、参考采样、前缀记录；复用原资产与成功判定 |
| `evotac/policy/` | ACT 推理与缓存适配；需要时兼容 `BasePolicy.eval/reset/close`，但不交给旧入口筛选场景或控制长动作块 |
| `evotac/models/`、`evotac/runtime/`、`evotac/learning/`、`evotac/evaluation/` | 编码器适配、历史网络、技能、状态机、训练与评估 |
| `evotac/data/` | 数据契约、旧数据转换、contact 加载、rollout 记录与训练 buffer；这里放代码 |
| `evotac/configs/`、`evotac/scripts/`、`evotac/tests/`、`evotac/docs/` | YAML、独立启动入口、必要测试和新增文档 |
| `evotac/datasets/` | 转换数据、新交互、场景清单与来源记录；原 `data/isaac51`、`data/contact` 只读引用 |
| `evotac/checkpoints/` | 下载的公开权重与新训练模型，记录来源 revision/哈希，不覆盖原模型 |
| `evotac/runs/`、`evotac/.cache/` | 日志、评估、视频、UIPC workspace 和可配置缓存 |

所有项目输出以 `evotac/` 绝对路径为基准，显式指定 `cfg.save_dir`，避免原 `auto` 路径。已有 `evotac/.gitignore` 忽略生成数据、权重和运行目录，源码照常提交。不搬迁或复制整批旧数据，不修改根目录的配置/脚本、原 `encoder/` 或 vendored TacEx。

实现顺序严格按阶段一至五推进，阶段六复用前面冻结版本和采集结果。不要先搭建大量网络再补控制接口，也不扩展通用框架、仪表盘或与可行性无关的基础设施。

## 四、完成标准与结论边界

**实现完成：** 六个阶段全部形成可执行产物，能够从失败采集走到候选接纳，并完成三组必要实验。

**可行性成立需分别给出证据：**

1. 加入触觉后，公共失败集合上的恢复表现优于无触觉对照。
2. 效果距离和经验检索相对普通效果预测，带来恢复选择或适应效率收益。
3. 持续适应改善新条件，同时满足预设旧能力保持要求。

结果按三个问题分别判定“支持 / 不支持 / 证据不足”，不以总体成功率上涨替代全部结论。没有观察到对应增益时如实记录，不通过扩大网络或无限追加实验替代判断。

有限扩展逻辑的实现不等于已经证明扩展有效；若固定技能库更新已足够，保留该结果。该计划首先验证单任务仿真可行性，不将结果外推为跨任务或真实机器人有效。
